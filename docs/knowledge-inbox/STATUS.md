## 処理の方針

- 送信された URL は調査の入口として扱う。同じテーマで、より参考になる資料（公式資料・一次情報・実測のある記事・広く検証された手法・今の版に合う資料）を探し、最も参考になるものを代表にする。成果は、持ち主の LLM 環境の改善（指示・rules・skills・hooks）と、知識の蓄積の 2 つ。
- 指示ファイルの正本は製品共通の `AGENTS.md` にする（持ち主の方針、2026-10-06）。`CLAUDE.md` は `AGENTS.md` を読み込む薄い入口とし、Claude Code に固有のことだけを置く。`foundation/` の `CLAUDE.md` 中心の雛形と文書は、指示ファイルを扱うグループの処理で `AGENTS.md` へ統合する。
- 52 件は、最初に Claude が同じ用途・適用条件のグループ（1 グループ 6 件まで）に分け、指示ファイルを扱うグループから処理する。グループの中は同じ会話で続けて処理する。記事ごとの実行権・検証・コミット・記録は 1 件ずつ行う。
- 共有した URL と、調べて実際に使った資料を分けて記録する。台帳の `intake`（`shared`・`found`）と `found_via`、生成する一覧 [../../knowledge/discovery-trails.md](../../knowledge/discovery-trails.md) を、PC 側が検証のあとに書く。`catalog` にも同じ 2 項目を入れる。
- 日付: 送信した記事は送信日時、一括登録した記事は記録された集計の基準（公開日・不明）を引き継ぐ。公開日が不明の記事は、元の記事で公開日を確かめられた場合だけ日単位で記録する。登録の日時や処理の日時では埋めない。成果の作成・配置・検証・公開は実際の日時で記録する。

## 処理の経過

- 2026-10-06 の 1 回目の「今すぐ処理」は、実行権の取得の段階で止まり、Firebase には何も書いていない。本番の Firestore は、利用者の ID トークンでの `beginTransaction` を拒否する（エミュレーターでは通る）。Web SDK と同じく、読んだときの更新時刻を条件に書き込む形に変えた。
- 回答を受けて、初期台帳の登録とグループの処理を始める。初回の処理のあと、入力の件数・処理済みの件数・成果の数・保留の理由を PR #7 に報告する。
