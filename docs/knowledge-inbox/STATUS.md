## 処理の方針

- 送信された URL は調査の入口として扱う。同じテーマで、より参考になる資料（公式資料・一次情報・実測のある記事・広く検証された手法・今の版に合う資料）を探し、最も参考になるものを代表にする。成果は、持ち主の LLM 環境の改善（指示・rules・skills・hooks）と、知識の蓄積の 2 つ。
- 指示ファイルの正本は製品共通の `AGENTS.md` にする（持ち主の方針、2026-10-06）。`CLAUDE.md` は `AGENTS.md` を読み込む薄い入口とし、Claude Code に固有のことだけを置く。
- 記事は、最初に Claude が同じ用途・適用条件のグループ（1 グループ 6 件まで）に分け、グループの中は同じ会話で続けて処理する。記事ごとの実行権・検証・コミット・記録は 1 件ずつ行う。
- 共有した URL と、調べて実際に使った資料を分けて記録する。台帳の `intake`（`shared`・`found`）と `found_via`、生成する一覧 `knowledge/discovery-trails.md` を、PC 側が検証のあとに書く。`catalog` にも同じ 2 項目を入れる。
- 日付: 送信した記事は送信日時、一括登録した記事は記録された集計の基準（公開日・不明）を引き継ぐ。公開日が不明の記事は、元の記事で公開日を確かめられた場合だけ日単位で記録する。登録の日時や処理の日時では埋めない。成果の作成・配置・検証・公開は実際の日時で記録する。
