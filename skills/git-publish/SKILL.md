# git-publish — 共有リポジトリへ入れる前の作法

## このスキルが解く問題

作業中の記録は、経緯を知っている読者を前提に書かれる。それをそのまま共有リポジトリへ入れると、
初見の読者が読めない文書と、秘密情報・個人情報・実在パスの混入が同時に起きる。

このスキルは、**書き方を直す手順**と、**機械検査で残りを止める仕組み**の2つで構成される。

## ルールの正本

共通運用ルール（命名・フォルダ構成・Git 運用・秘密情報）を定めたリポジトリがあれば、その `CONVENTIONS.md` が正本である。
**このスキルはその実装であり、正本ではない。** 共通運用ルールが無ければ `config/policy.json` が正本になる。

組織固有の判断（許可する組織アカウント、匿名化されたパスの形、履歴ブリーフのパス、運用ログのパス）は、
このリポジトリの `config/policy.json` に置く。**スクリプト本体に組織名・URL・端末パスを直書きしない。**

判定を変えるときは、①共通運用ルールの `CONVENTIONS.md`（あれば） ②`config/policy.json` ③スクリプトと
`tests/` の順に更新する。

## 手順

1. **対象を確定する。** リモートの所有者、可視性、対象ブランチ、想定読者を確認する。
   公開範囲を変える操作は、実行者の明示的な承認を得てから行う。
2. **作業ツリーの状態を見る。** `git status --short`、差分、追跡ファイル、`.gitignore` を確認する。
   関係のない変更を巻き込まない。**対象パスだけを明示して stage する。**
3. **初見の読者向けに書き直す。** 判断の基準は [references/writing_register.md](references/writing_register.md)。
4. **機械検査を実行する。** 記憶に頼らず毎回実行する。

   ```bash
   python skills/git-publish/scripts/preflight.py --repo <対象リポジトリ> --scope staged
   ```

   初回公開時は `--scope all` で追跡ファイル全体を検査する。
   レシートの出力先は `--receipt-dir` で指定する。既定は一時ディレクトリで、
   **エージェントの home へは書き込まない。**
5. **BLOCK をすべて解消する。** 解消してから再実行する。
   **`--force` と抑制マーカーで恒久的な検出を通し続けない。** 判定を変える必要があるなら、
   上の「ルールの正本」の順序で規約と設定を先に直す。
6. **WARN は昇格させない。** ただし公開時は、**実測件数・件数の多い規則・残す理由・残余リスク**を
   PR 本文へ記録する。「検査を通した」とだけ書かない。
7. **1コミット1目的でコミットし、ブランチと PR を既定にする。** 既定ブランチへ直接 push しない。
8. **引き継ぎに何を書くか。** 変更したパス、実行した検査とその結果、リモートとブランチ、
   **意図的に検証していないこと**を書く。
9. **main に入るまでを 1 つの作業にする。** PR を作ったら、その場でマージまで通すか、レビューを
   誰に頼んだかを書く。「push した」で終えない。開いたままの PR は、main を見る人には存在しないのと同じである。
   `git ls-tree origin/main <path>` で main にあることを確かめてから「入った」と書く。

## 検査の結果を読み違えない

- **検査とコミットを 1 つのコマンドに繋がない。** `preflight.py ... | grep BLOCK && git commit` は、
  grep が 1 行でも拾えば終了コードが 0 になり、BLOCK があってもコミットが走る。検査は別に実行し、
  `[BLOCK]` の件数が 0 であることを見てから、別のコマンドでコミットする。
- **未追跡のファイルは検査に現れない。** `git diff --check` も `--scope staged` も、追跡していない
  ファイルを見ない。出力が空なのは、対象が空だっただけのことがある。記録には「何を・いつ・どの tree に
  対して」検査したかを書き、公開した後の tree に走らせた結果を公開時の証拠として書かない。
- **同じリポジトリで別の人やセッションが並行して作業していることがある。** PR を作る前と、Git を正本に
  外部へ配信する前に `git fetch` で origin/main の位置を見る。配信したときは、どのコミットから配信したかを残す。

## 検査が見るもの

| 種別 | 規則 | 例 |
| --- | --- | --- |
| 秘密情報 | `S01`〜`S14` | 鍵・トークン・パスワードの直書き、認証ファイル、`.env` |
| 個人情報 | `P01`〜`P04` | 個人のメールアドレス、個人への言及、著者名と一致する氏名 |
| 実在パス | `L01`〜`L04` | 利用者ディレクトリを含む絶対パス（匿名化された形は許容） |
| 文体 | `C01`〜`C09` | 会話文脈、一人称・二人称、会話体、内部プロセス用語、相対日付、未確定の口約束 |
| 構成 | `T01`〜`T14` | スクラッチ名、曖昧な版名、生データ、`README` / `.gitignore` / `docs` の欠如 |
| エンコーディング | `E01`〜`E03` | 種別ごとに要件が反転する（`.ps1` は BOM 必須、`.json` は BOM 禁止、`.sh` は LF） |

規則の本体は [scripts/preflight.py](scripts/preflight.py) にある。**規則の一覧をこの文書に複写しない**
（片方だけ更新される状態を作らないため）。

`--scope` ごとに、規則を掛ける範囲が違う。

| `--scope` | 文体（`C01`〜`C09`） | 秘密情報・個人情報・実在パス・構成・エンコーディング |
| --- | --- | --- |
| `staged` | staged の差分で**足した・変えた行だけ**。新しいファイルは全部の行。名前を変えただけで中身を変えていないファイルには掛けない | 変えたファイルの全部の行 |
| `all`・`head` | 対象のファイルの全部の行 | 対象のファイルの全部の行 |

`staged` で文体を変えた行だけに絞るのは、履歴の文書へ書き足すときに、変えていない既存の行（当時の言い回しや、
記録として残す語の表など）で止めないため。変えていない行でも、秘密情報・個人情報・実在パスは止める。
差分から行の番号を取れなかったファイルは、厳しい側（全部の行）に倒す。

## 3つの恒久例外

規約が明示的に許容し、設定で表現しているものが3つある。詳細は
[../../config/POLICY.md](../../config/POLICY.md)、境界の確認は
[../../tests/test_preflight.py](../../tests/test_preflight.py)。

1. **組織アカウント識別子** — 台帳・remote・所有者の表記に必要なもの。理由付きの allowlist で1件ずつ許可する。
   個人名・個人アカウント名・個人のメールアドレスは対象外。
2. **匿名化されたパスの形** — 利用者名の位置を伏せた表記。実在の利用者名を含む絶対パスは検出する。
3. **原文保持の実装ブリーフ・完了記録** — 会話文脈の規則だけを外す。
   秘密情報・個人情報・実在パスの検査は継続する。

## 自動ゲートは置かない

**commit / push を自動で止める仕組みは同梱していない。検査は手順として毎回実行する。**
実行していない場合は、その事実を引き継ぎと PR 本文に書く。「検査を通した」と書かない。

コマンドの文面を読んで止める PreToolUse フックで「検査なしの push を止める」を保証しようとしない。
同じ目的の見張りを監査した記録では、回すたびに新しい抜け（環境変数での git の向け先の変更、
heredoc、シェルの旗の束、コメント中の引用符、文字コードなど）が見つかり、その半分は前の回の直しで
入った後退だった。書き方は尽くせない。

- 保証は、書き方に左右されない所に置く。git の `pre-push` は送る先の枝を git 自身が渡す。
  サーバー側のブランチ保護も同じである。
- 見張りを置くなら、役目をその保証を外す操作（`--no-verify`・`core.hooksPath` の付け替え・
  フックのファイルの移動）を止めることに絞る。
- 検査のレシートを使う仕組みを作るときは、レシートを**これから確定する内容（tree）**に結び付け、
  置き場所を `config/policy.json` の `receipt_root` の 1 か所だけに書く（詳細は
  [../../config/POLICY.md](../../config/POLICY.md)）。

フックが登録されているかは `agent-config-inventory` skill で確認する。**ファイルの存在は
稼働の証明ではない。** 登録されていない状態で「ゲートが止める」と書かない。

## 検査が見ないもの

- **日本語の実名を検出する辞書を持たない。** 個人名の照合は、対象リポジトリの著者名との一致だけである。
  **検査の通過は「個人情報が無い」ことの証明ではない。**
  GitHub が画面・API でのマージに使う署名（`GitHub <noreply@github.com>`）は人ではないので照合に入れない。
  同じコミットの著者（人）は照合を続ける。
- 抽出できないバイナリ、画像の中の文字、リンク先の内容。
- 既定では対象のファイルを全部見る。`--max-files` で上限を付けたときは、超えると検査せずに終了コード 2 で止まる（一部だけを見て通すことはしない）。
