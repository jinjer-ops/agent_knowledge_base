# 外へ出せない資料を扱うとき、どこまで手元に置くか

**この手引きはこの環境で実測していません。** 手元で動かす構成は一度も組んでおらず、特定の
実行基盤・モデル・埋め込みモデルの導入を勧めるものではありません。状態は `experiment` です。
公式の記述から引いた内容は確認した時点のもので、契約区分と設定は自分のところで引き直します。

## 何の問題を扱うか

起動条件は、**扱う資料を外へ出したくない（出せない）ので、手元で動かす構成を考え始めたとき**です。

隣接する手引きはどれも費用が起点で、ここだけが制約が起点です。

| 手引き | 起点 | 問い |
| --- | --- | --- |
| [../model-tier-selection/](../model-tier-selection/) | 費用 | どの段のモデルで始めるか |
| [../heavy-read-delegation/](../heavy-read-delegation/) | 費用 | 1 回ごとの重い読み取りをどこへ逃がすか |
| [../review-design/](../review-design/) | 費用・品質 | 判断そのものを別のモデルへ回してよいか |
| [../retrieval-structure-decision/](../retrieval-structure-decision/) | 構成 | 事前に索引を作るか、その場で探すか |
| ここ | **制約** | **置き場所が、選ぶ前から決まっているか** |

## まず、「外へ出さない」を手元で動かすことと同じにしない

「完全ローカル」という言い方は、中身の違う 3 つの要件をひとまとめにします。先に分けます。

1. **送ったものが学習に使われないこと**
2. **送ったものが保持されないこと**（どれだけの期間、どこに）
3. **そもそもネットワークの外へ出ないこと**

1 と 2 は、提供元の記述と自分の契約区分・設定で満たせる場合があります。公式の記述（`REF-099`）
からは次が読めます。

- **商用の契約では、送ったコードやプロンプトを生成モデルの学習に使わないと明記されています。**
  利用者が明示的に提供を選んだ場合（開発パートナーの制度など）は別です。消費者向けの契約は
  設定によって扱いが変わり、学習に使う設定を選んだ場合と選ばない場合で保持期間も違います。
- **保持期間は契約区分で違います。** 商用の既定は 30 日、無保持の取り決めは標準の契約には含まれず、
  組織ごとに有効化される別の取り決めです。
- 自動の検査に引っかかった場合など、無保持の取り決めがあっても保持されうる例外が書かれています。

つまり、要件が 1 と 2 だけなら、**手元で動かす前に契約と設定の側で確かめる**のが先です。
手元で動かす以外に手が無いのは 3 だけです。

### 「外」だけを見ていると見落とす 2 か所

同じ公式の記述から、方向の違う 2 点（`REF-099`）。どちらも手元で動かすかどうかとは別に効きます。

- **手元にも残ります。** 会話の記録は手元に平文で保存され、既定の保存日数があります（設定で
  変えられます）。送信先の管理だけを厳しくしても、手元の平文の記録は別に扱う必要があります。
- **送り先を替えても止まらない経路があります。** 取得前のドメイン照会はホスト名を送り、
  モデルの提供元を切り替えても既定では動きます。止めるには別の設定が要ります。会話の履歴を
  含めて送る経路（フィードバックの送信）も、それ自身の設定で止めます。

**「どのモデルへ送るか」と「何がどこへ出ていくか」は別の問いです。** 後者は設定の一覧から
数え上げるもので、モデルを手元に置いたことで自動的に解決しません。

## 「完全ローカル」は、一括りの選択ではない

資料を手元で検索して答えさせる構成は、少なくとも 3 つの部品からできています。手元に置く
難しさは部品ごとに違うので、**まとめて決めない**ほうが選択肢が増えます。

| 部品 | 手元に置く難しさ | 効いてくる制約 |
| --- | --- | --- |
| 埋め込み（索引を作る） | 低い。モデルが小さく、一度作れば使い回せる | 言語と用途への適合 |
| 格納・取り出し | 低い。計算ではなく保存の問題 | 毎回作り直さない（永続化） |
| 生成（答えを書く） | 最も高い | 容量、速度、文脈長 |

ここから、ひとまとめの「全部手元」以外に、要件に応じた中間が取れます。

- 要件が**資料の中身を外へ出さないこと**なら、索引と取り出しを手元に置き、
  取り出した断片ではなく**問いの文面だけ**を外へ出す構成がありえます。
- 全部を手元に置く必要があるのは、**問いの文面すら出せない**場合です。

入口の記事（`ART-005`）はこの 3 部品を一台の機材に載せた記録で、構成の実例としては読めますが、
**要件をこの形で分けてはいません。** 分ける作業はこちらでやります。

生成を手元へ置くと決めた場合、選ぶ軸は段ではなく「容量に収まる範囲でどこまで圧縮するか」に
変わります。測定にもとづく整理は [../model-tier-selection/](../model-tier-selection/) にあります。

## 埋め込みは、使う言語の評価で選ぶ

埋め込みは手元に置きやすい部品ですが、**既定で多言語の汎用モデルを選ばない**ようにします。
日本語には、分類・クラスタリング・意味的類似・検索・再順位付けの 5 種類の課題、28 のデータ
セットで埋め込みモデルを評価する公開の枠組みがあり（`REF-103`、CC-BY-SA-4.0）、順位は
現在 MTEB の言語別の一覧に移っています。

読み方は 2 つです。

- **用途に近い課題の順位を見る。** 資料を検索させるなら、総合の平均ではなく検索と再順位付けの
  側を見ます。平均は用途の違う課題を混ぜた値です。
- **順位は自分の文書での性能ではありません。** 公開のデータセットで測った値なので、最後は
  自分の資料から質問と正解の対を少数作って比べます。この比較は手元で完結します。

## 手元で動かすと、黙って壊れる場所がある

手元の実行基盤には、**入力が文脈長を超えたときに何も言わずに切り詰める経路**があります
（`REF-084`）。既定の文脈長と設定経路は提供元の記述が正本ですが、超えた場合の挙動はそこに
書かれていません（`REF-083`）。

資料を取り出して詰め込む構成は、この境界にいちばん当たりやすい形です。そして切り詰められた
入力を見たモデルは、**「該当する記述はありません」と答えます。** 見ていないことと、見た上で
無かったことが区別できません。

対処は 1 つだけです。**送った量と処理された量を突き合わせ、入りきらないときは止める。**
同じ故障は、取り出し方の実験でも誤りの主要因として観測されています
（[../retrieval-structure-decision/](../retrieval-structure-decision/)）。

## 確かめる手順（charter）

- **用途**: 手元で動かす必要が本当にあるのか、あるならどの部品かを、推測ではなく確認した事実で決める。
- **入力**: 自分の契約区分とその提供元の現在の記述、手元の設定、扱う資料の種類、
  その資料から作った質問と正解の対（少数でよい）。
- **安全境界**: 確認作業そのもので資料を外へ出さない。評価用の質問に実際の資料の中身を貼らない。
  比較の記録に資料の本文を残さない。
- **検証方法**:
  1. 要件を 1・2・3 のどれかに決める。3 でなければ、契約と設定で満たせるかを公式の記述で確かめ、
     そこで止める。
  2. 3 の場合、部品ごとに手元へ置く必要があるかを表の順に判定する。
  3. 置くと決めた部品について、文脈長を超えたときに止まるかを**わざと超える入力で 1 回確かめる**。
     黙って通ったら、その構成は合否を信用できない。
  4. 自分の質問と正解の対で、外へ出す構成と手元の構成を同じ問いで比べる。
- **終了条件**: どの部品を手元に置くかが決まり、3 の確認で止まることを見たら終わり。
  要件が 1・2 だけだと分かった時点で終わることもあり、その場合は**何も作らない**のが結論になる。

## 限界

- **この環境では一度も組んでいません。** 上の手順は未実行で、手順自体の有効性も確かめていません。
- `REF-099` は一つの提供元の記述です。ほかの提供元では学習の扱いも保持期間も違うので、
  使っている提供元ごとに引き直します。引用した内容は確認した時点のもので、改定されます。
- `ART-005` は機材 1 台の構築記録で、比較対照も再現もありません。採ったのは部品の構成と、
  「埋め込みを毎回作り直すと破綻する」という運用上の指摘だけで、速度や容量の数値は移していません。
  機材が違えば数値も変わります。
- `REF-103` は評価の枠組みであって、モデルの推薦ではありません。順位は提出された時点の値で、
  自分の資料での性能とは別です。
- 文脈長の扱い（`REF-083`・`REF-084`）は一つの実行基盤についての記述と報告です。別の基盤を
  使うなら、同じ故障があるかを自分で確かめます。
