# Claude Code starter

## 最小構成

指示の正本はツール非依存の `AGENTS.md` に置きます（[../agents-md/README.md](../agents-md/README.md)）。Claude Code 側には、固有の内容がある場合だけ `CLAUDE.md` を置き、必要な場合だけ `.claude/rules/` と `.claude/skills/` を追加します。

```text
project/
├─ AGENTS.md            # 正本。全エージェント共通の作業合意
├─ CLAUDE.md            # 任意。Claude Code 固有の指示だけ
└─ .claude/
   ├─ rules/
   │  └─ review.md
   └─ skills/
      └─ <skill-name>/SKILL.md
```

雛形は [../agents-md/AGENTS.md.template](../agents-md/AGENTS.md.template) と [CLAUDE.md.template](CLAUDE.md.template)、レビュー時の補助観点は [rules/review.md](rules/review.md) を使います。

## 置き場所の判断

| 内容 | 置き場所 | 例 |
| --- | --- | --- |
| ほぼ全作業で必要な短い事実 | `AGENTS.md` | 目的、技術スタック、検証コマンド |
| Claude Code にしか意味のない指示 | `CLAUDE.md` | plan モードの使い分け、固有機能の扱い |
| 対象ファイルや用途が限定された方針 | `.claude/rules/` | レビュー、資料作成、データ変更 |
| 起動条件・入力・検証・停止条件がある反復作業 | `.claude/skills/` | 公開前確認、文書取り込み |
| **指示では確実にできないこと**（必ず止める、必ず記録する、毎回知らせる） | hook | 破壊的な操作の拒否、保存後の整形、上限の監視 |
| 画面に出す、Claude Code 自身の描画や挙動を関数で差し替える | mod（コードを持つ plugin） | 残量を示す枠の追加、危険なコマンドを保留して利用者に尋ねる |
| 長い背景・設計理由・記事 | リポジトリの文書 | ADR、実験記録、参考資料 |

常時読み込まれる層は短く保ち、手順を丸ごと貼り付けません。詳細が必要な作業はskillまたは参照文書へ移します。ファイルを分けるだけでは起動時の消費は減らず、呼び出し式の層へ移したときに減ります。

指示は context であって強制ではないので、確実に効かせたいことは hook に置きます。ただしイベントごとに**止める力があるかどうかが違い**、ツールの実行後に走るイベントでは止められません。どのイベントで何ができるかは `REF-020` を読んでから決めます。そのうえで、**hook に置けば必ず止まる、とは言えなくなりました**。条件は次節にあります。

### 止める力がどこにあるか（mod が増えた）

2026-10 の版から、Claude Code には **mod** という層が加わり、既定で有効になっています（`REF-120`、確認日 2026-10-07）。mod は plugin の中に JavaScript / TypeScript の関数を置き、ツール呼び出し・プロンプト・画面描画といったイベントを **Claude Code のプロセスの中で**受け取ります。設定ファイルに書く従来の hook（外部コマンド・HTTP・プロンプト）は廃止されておらず、並んで動きます。上の表で hook と mod を分けたのは、できることが違うからです。止める・記録するだけなら hook、画面に出す・Claude Code 自身の描画を置き換える・イベントを別の値に書き換えるなら mod、という分かれ方になります。

**順序が判断を変えます。** 同じツール呼び出しに対して、どこに置いた拒否が最終なのかは次のとおりです（`REF-121`、`REF-122`）。

| 置き場所 | ツール呼び出しに対する強さ |
| --- | --- |
| 管理設定の `PreToolUse` hook | mod より先に走り、ここでの拒否が最終。mod は覆せない。mod が呼び出しを書き換えた場合は書き換え後にもう一度走る |
| `deny` の権限ルール | 同梱の保護 mod が読み込まれている環境でだけ、利用者の mod から覆せない |
| **それ以外の設定ファイルの `PreToolUse` hook**（利用者個人の設定を含む） | mod の**後**に走る。mod が自前で結果を返すとそもそも走らず、走っても後続の判定イベントで許可へ変えられる |

つまり、個人の設定に置いた hook は「必ず止まる」ではなく、**「mod を入れていなければ止まる」** です。mod を 1 つも入れていない環境では今までと同じですが、入れる判断をするときにこの差が効きます。

**保護 mod は、どの環境にもあるわけではありません。** 利用者の mod から `deny` ルールを守る同梱の保護 mod が読み込まれるのは、管理設定がある機械か、Team / Enterprise の契約でサインインしている場合だけです（`REF-122`）。どちらでもない個人の機械では、この保護自体が載りません。自分がどちらなのかを先に確かめます。

**止める側は、失敗すると通す側へ倒れます。** mod の hook が例外を投げる・時間上限を超えると、Claude Code はその hook を飛ばして次へ進みます。止めるために置いた処理なら、失敗時に拒否を返す処理を同時に登録しておかないと、落ちた瞬間に素通りします（`REF-121`、`REF-123`）。これは従来の hook でも同じ向きの注意です。

**mod は隔離されていません。** 利用者と同じ権限で動き、ファイルの読み書き、プログラムの起動、ネットワーク接続、環境変数と設定ファイル（API キーを置いていればそれも）の読み取りができます。サンドボックスを有効にしていても、mod が起動したプロセスはその外で動きます（`REF-120`）。入れる前に、その plugin のディレクトリに対して検証のコマンドを実行すると、**受け取るイベントの一覧と、呼び出す API の一覧**が実行せずに出ます（`REF-122`）。見る対象は次のとおりです。

- イベント側: すべてのツール呼び出しとプロンプトを見て書き換えられるもの、権限の確認より前に許可・拒否を決められるもの、会話の各行を保存前に書き換えられるもの
- API 側: ファイルの読み書き、プロセスの起動、ネットワーク接続、環境変数と設定の読み取り、利用者の契約枠を使うモデル呼び出し、利用者本人の言葉としてプロンプトを送るもの

**一時的に全部止める**には、セッション単位で安全起動の指定、恒久的には利用者設定で全 hook を無効にする項目があります。後者は自分の設定した hook と状態表示も同時に止まります（`REF-123`）。同梱の mod はこれらでは止まらず、個別の切り替えになります。

ここに書いたのは公開されている仕様から読み取った内容で、この環境では mod を導入していません。導入を勧めるものでもありません。版への依存が大きい領域なので、実際に使う版の公式資料を読み直してください。

### 止められなかったときに戻せる層（チェックポイント）の境界

止める層の話には続きがあります。**止まらなかったときに、何がどこまで戻るか**です。
この製品はセッション中のファイル編集を自動で記録し、`/rewind` で戻せます（`REF-202`、
確認日 2026-10-26）。ただし境界が明確で、**上の表で hook に預けている「破壊的な操作」の多くは
この層に入りません**。

| 何をしたか | 巻き戻るか |
| --- | --- |
| 組み込みの編集ツールがファイルを変えた | 戻る |
| **編集ツールが一度も触っていない**ファイルを、シェルが変えた・消した | **戻らない**（そのまま残る） |
| 一度編集ツールで触ったファイルを、その後シェルが変えた | 戻る |
| **背景で動くサブエージェント**が、会話で触っていないファイルを変えた | **戻らない** |
| symlink / hard link の先 | **飛ばされる**（警告だけが出る） |
| セッションの外・並行する別セッションの変更 | 戻らない |

**期限もあります。** セッションあたり直近 100 件まで。既定では、そのセッションが最後に記録してから
約 30 日ほどで掃除され、その後の巻き戻しは `No files were restored` で失敗します。
保持を延ばす設定項目はあります。そして公式自身が **「Not a replacement for version control」** と
書いています。

ここから、この環境に効く条件が 2 つ出ます。

1. **下位エージェントに並列で書かせる構成では、この層は当てにできません。** 背景のサブエージェントや
   背景の forked skill に編集させるなら、受け皿は版管理の側に置きます。
2. **`-p` の自動実行で消す・動かす操作をさせるなら、シェル経由かどうかが分かれ目です。**
   スクリプトや `mv` が作った成果物は、コミットするまでどの層にも入っていない状態になりえます。

止める層と戻す層は別物で、片方を厚くしても片方は埋まりません。層の数え方と、
版管理側の期限（reflog・`gc`）を含めた全体は、製品に依存しないので
[../change-recovery-layers/](../change-recovery-layers/) にまとめてあります。
ここに書いた既定値は版に依存します。この環境では巻き戻しを一度も試していません。

### 秘密を置いたファイルを読ませない

資格情報を置いたファイルは、権限の `deny` に `Read` のルールを足して読み取りの対象から外します（`REF-145`）。`deny` は `ask`・`allow` より先に判定され、`allow` 側から例外を切り出せません。`Read` の拒否は同じパスへの `Edit` と `Write` にも及びます。パターンは gitignore と同じ書き方で、`Read(.env)` は配下の任意の深さに当たります。利用者設定に書くルールは、何も付けないと利用者の設定ディレクトリ基準になるため、すべてのプロジェクトに効かせるには絶対パスか home 起点の書き方にします。`.claudeignore` は効きません。

**どこまで効くかに境界があります。** 公式の記述では、`Read` と `Edit` の拒否が及ぶのは、組み込みのファイル操作、`cat`・`head`・`tail`・`sed`・`tee` のように Claude Code が解釈できる形でパスを名指ししたシェルの呼び出し、そして `> file` や `< file` のリダイレクト先までです。**パスを名指ししない読み取り**（その場所で走らせた `grep -r`）や、**自前のスクリプトが開くファイル**（Python や Node が自分で開く場合）には及びません。すべてのプロセスに対して止めるなら、サンドボックスを有効にする側の設定になります（`REF-145`）。

したがってこの層は「エージェントが普通に読む経路を閉じる」ものであって、秘密が文脈へ入らない保証ではありません。秘密そのものの扱い（どの層で何が止まり、漏れた後に何をするか）は [../secret-exposure-layers/README.md](../secret-exposure-layers/README.md) にまとめてあります。

ただし skill 側へ移しても費用が消えるわけではありません。読み込まれた skill の本文は会話に残り続け、読み直されません。移した内容は、一度きりの手順ではなく作業の間ずっと効く指示として書き直します。書き方と確認の手順は [../skill-authoring/README.md](../skill-authoring/README.md) にあります。

## 自動実行（`-p`）が起動時に読み込むもの

対話ではなく script や定期実行から呼ぶ形（`-p`）は、**1 回のモデル呼び出しではなく、
対話と同じ道具・同じエージェントのループ**です（`REF-200`、確認日 2026-10-13）。
読み込む範囲も既定では対話と同じで、作業ディレクトリと `~/.claude` にあるものが入ります。

このことは、公式資料が用意している**自動探索を飛ばす指定**の説明に裏側から書かれています。
その指定は「起動時間を減らす」ためのもので、飛ばす対象として hook、skill、カスタムコマンド、
サブエージェント、導入済みの plugin、接続する外部ツール、自動の記憶、`CLAUDE.md` が
挙げられています。外部ツールを明示して渡した場合は、接続待ちに既定で数十秒の上限があります。

ここから、この層で言えることが 3 つあります。

1. **起動側に、測れる量の時間がある。** 速度を比べるときにこの呼び出しを基準線に置くと、
   測っているのはモデルではなく起動と往復を含む経路になります。この読み違えの一般形は
   [../typed-decision-gating/](../typed-decision-gating/) にまとめてあります。
2. **機械ごとに結果が変わる。** 飛ばす指定を付けない限り、同僚の `~/.claude` にある hook や
   プロジェクトの外部ツール設定がそのまま走ります。CI や定期実行で**どの機械でも同じ結果**が
   要るなら、飛ばす側を既定にします。
3. **信頼していないフォルダでも、置かれた処理が走る。** `-p` の実行では、プロジェクトの
   設定ファイルにある hook が動き、設定された外部ツールへ接続します。信頼を尋ねる画面も
   サーバごとの承認も出ません。他人のリポジトリに対して自動実行を向けるときは、
   飛ばす指定を付けるか、そもそも向けないかのどちらかです。

飛ばす指定には代償があります。自分で入れた rules・skills・hook も同時に効かなくなるので、
**必ず効かせたい処理をそこに置いている場合は、用途ごとに選びます。** 認証の経路も変わります。
いずれも版に依存するため、使う版の公式資料で確かめてください。この環境では、この指定の
効果を実測していません。

## AGENTS.md との関係

Claude Code は、作業ディレクトリとその上位に `CLAUDE.md` / `.claude/CLAUDE.md` / `CLAUDE.local.md` が無いときに `AGENTS.md` を直接読みます。判定に数えるのはプロジェクト側のこれらだけで、ユーザー個人の `~/.claude/CLAUDE.md`、組織の管理ポリシー、`.claude/rules/` は数に入らず並んで読み込まれます。

両方を読ませる設定はユーザー設定・管理設定だけで有効で、プロジェクト設定からは指定できません。リポジトリ側から確実に効かせたい場合は、`CLAUDE.md` の先頭で `AGENTS.md` を取り込みます。Windows を含むチームでは symlink ではなく取り込みを使います。条件と制約は [../agents-md/README.md](../agents-md/README.md) にまとめてあります。

## Windows で動かす場合

同じ設定でも、**どのシェルの道具が使われるかが機械によって変わります**（`REF-161`、確認日 2026-10-13）。
Git for Windows が入っていれば Bash の道具が使われ、入っていなければ PowerShell の道具が使われます。
両方が揃っている構成では両方が並び、どちらを使うかはその場の判断になります。Bash が見つからない場合に
場所を指定する環境変数も用意されています。

**Windows でそのまま動かす構成では、サンドボックスが利用できません**（`REF-161`）。隔離を前提にした
判断（「危なければサンドボックスで止まる」）は、この構成では成り立ちません。前節の止める層の話は、
サンドボックスが無い前提で読みます。

どちらの道具が選ばれたかは、生成されるファイルの符号化と改行にそのまま出ます。日本語を含む
スクリプトや設定ファイルを書かせる場合、どちらの処理系がそれを読むかで正解が変わり、
片方に合わせるともう片方が壊れます。クラウド同期フォルダの下では、編集が黙って失敗する経路も
報告されています。この層の判断は、製品に依存しないので
[../windows-file-hazards/](../windows-file-hazards/) にまとめてあります。

## 大きなリポジトリ

階層が深い、または package が多いリポジトリでは、根に 1 枚だけ置く構成が「全部入りで重い」か「汎用的すぎて役に立たない」のどちらかに寄ります。根に全体の規約、各領域にその領域の規約、という二層に分け、関わらない領域の指示を除外する設定と、対象を絞るルールを併用します。どこで起動するかで読み込まれる範囲が変わる点が起点になります。設定と判断の詳細は `REF-008`、正本を `AGENTS.md` にする場合の追加の注意は [../agents-md/README.md](../agents-md/README.md) にあります。

## 導入後の確認

1. 新しいセッションで、プロジェクトの目的と検証方法をClaudeに要約させる。
2. どの指示ファイルが実際に読み込まれたかを、セッション内で占有の内訳を出す機能で確認する（`REF-017`）。読み込みの形跡を確認するまで適用済みと扱わない。
3. `.claude/rules/` を追加した場合は、対象の作業でだけ参照されることを確認する。
4. skillを追加した場合は、`SKILL.md` の説明だけで起動条件が判別できることを確認する。あわせて、入れる前と入れた後で対象の作業を比べる（[../skill-authoring/README.md](../skill-authoring/README.md)）。

Claude Codeの現在のファイル配置・読み込み仕様は `REF-001` と `REF-002` を正本とします。版によって `AGENTS.md` の扱いが変わるため、導入時に読み直します。

## 共有skillの導入

このリポジトリの [skills/](../../skills/) から必要なskillディレクトリだけを、プロジェクトの `.claude/skills/` または利用するエージェントのskillディレクトリへコピーします。ローカル設定、認証情報、履歴、許可情報はコピーしません。
