# 動く成果物を作らせるとき

**この構成はこの環境で運用していません。** 根拠は査読済みのメタ分析 1 件、公式資料 5 件、
参考資料 1 件、入口の記事 1 件です。状態は `experiment` です。

起動条件は「**エージェントに、動くもの（解説アニメーション、画面の遷移、動画）を
作らせようとしたとき**」です。

隣の手引きとの違いは、**時間軸があるか**です。
[../diagram-as-text/](../diagram-as-text/) は図そのものの正しさ、
[../design-asset-canon/](../design-asset-canon/) は画面の見た目の正本、
[../presentations/](../presentations/) は資料の形式。いずれも止まっているものを扱います。
動き出すと、確かめる対象が 3 つ増えます。**同じ入力から同じ映像が出るか、
見ている人を害さないか、音に対応する文字があるか**です。

## まず、動かす価値があるかを決める

動かすかどうかには査読済みの測定があります（`REF-170`、61 の研究・参加者 7,036 名・
140 組の対比を集めたメタ分析）。結論は「効くが、小さい」です。アニメーションが静止画に
勝る効果量は小さく、条件によって大きく変わります。採る価値があるのは、**どの条件で
伸びたかという向き**の方です。

| 条件 | 向き |
| --- | --- |
| 速度を見る側が操作せず、作り手が決める | 伸びる |
| 音声の解説を付ける | 伸びる |
| 同じ内容の**文字を併記しない** | 最も大きく伸びる |

つまり「とりあえず動かす」は小さい改善しか生みません。**伸びるのは、変化の過程そのものを
見せる必要があり、その説明を音声に寄せ、同じ説明を文字で二重に出さない場合**です。
逆に言えば、静止した図とキャプションで足りる内容を動かしても、手間に見合いません。
数値はこの環境で再現していないので、手引きへは向きだけを移しています
（値は [../../knowledge/reading-guide.md](../../knowledge/reading-guide.md) のカードにあります）。

ここには、後の節の規約と**正面から衝突する点が 2 つ**あります。先に書いておきます。

1. 「文字を併記しない方が効く」と、「音声には字幕を付ける」（`REF-173`）は逆を向きます。
2. 「作り手が速度を決める方が効く」と、「自動で動き続けるものには停止手段を置く」
   （`REF-172`）も逆を向きます。

どちらも、**既定でどう見えるかを分けることで両立します**。字幕は用意した上で既定では
出さない、自動再生は他の内容と並べない、という形です。衝突を知らずに「効く方」だけを
採ると、規約の側を落とします。

## 正本はコードか、映像か

動くものを作らせる経路は 2 つあります。映像を直接生成させるか、**動きをコードで書かせて
描画させるか**です。送信元の話題（`ART-048`）は後者で、動画生成 AI 向けに書かれた
プロンプトをそのまま汎用のモデルへ渡したところ、コードで描いた解説アニメーションが
返ってきた、という報告です。

この選択で決まるのは出来栄えではなく、**出した後に何ができるか**です。
[../diagram-as-text/](../diagram-as-text/) と同じ形で、正本がテキストなら版管理の差分が
読め、1 ショットだけ直すことができます。映像ファイルが正本なら、直す単位は作り直しです。

ただし図と違い、**テキストを正本にしても「同じ記述から同じ映像が出る」ことは自動では
保証されません**。隣の手引きには「実行ごとに変わるのは配置であって、図の記述そのものでは
ない」と書いてあります。時間軸が入ると、この前提が崩れる経路があります。

## プレビューで動いたものが、書き出すと壊れる

コードから映像ファイルを作る処理系の公式資料に、理由が具体的に書かれています
（`REF-169`）。その処理系は**フレームを並列に描くために、ページの実体を複数立ち上げます**。
そのため `Math.random()` のような値はフレームごとに別々の結果を返し、
**画面で再生する間は正しく見えるのに、書き出した映像で壊れます**。

公式の対処は、乱数を種から決めることです。同じ種を渡す限り同じ値が返るので、
並列に描いても食い違いません。例外として、メタデータを計算する段では真の乱数でよいと
明記されています。そこは 1 回しか、並列でなく呼ばれるからです。

この環境で採るのは、処理系の採否ではなく**故障の形**です。

- **時刻と乱数に依存する動きは、再現できない。** 現在時刻、`Math.random()`、
  起動からの経過時間に依存させず、**フレーム番号（または経過時間の明示的な入力）から
  計算する**形に寄せる。
- **確認するのは書き出した結果であって、プレビューではない。** これは
  [../presentations/](../presentations/) の「ソース側が正しく見えることは、出力側で
  切れていないことの証拠にならない」と同じ構造です。
- 送信元の記事は、生成されたものをどう映像ファイルにしたかを書いていません。
  **画面録画で済ませたのか、フレーム単位で描いたのかで、再現性は別物になります。**
  録画は実行時の負荷に左右されるので、同じ入力から同じ映像が出る保証を失います。

なお、この処理系自体の利用条件（商用利用で有償ライセンスが要るか）は確認できませんでした。
**導入は勧めません。** 採ったのは上の 3 点だけです。

## この環境で、実際に何が成立するか

手元の製品で動くものを作って共有する場合、できることは公式資料に明示されています
（`REF-168`）。成果物は **1 枚の自己完結した HTML ページ**で、厳しい内容セキュリティ方針の
下で配信されます。版に依存するので採用時に読み直す前提ですが、設計を変える制約が 4 つあります。

| 制約 | 動くものを作るときに何が起きるか |
| --- | --- |
| 外部への通信 | 外部の画像はすべて遮断。スクリプトは 5 つの公開 CDN のみ。`fetch`・XHR・WebSocket は自分のオリジンと字体の配信元にしか届かない。**外部に置いた動画・音声・素材を参照する構成は動かない。** |
| ページ自身のダウンロード | **ページが自分で始めるダウンロードは遮断される**（`data:` や `blob:` へのリンクも含む）。保存させたいなら、公開時にその能力を宣言する必要がある。 |
| 描画後の大きさ | 16 MiB 以下。素材を data URI で埋め込む方式は、ここに早く当たる。 |
| 単一ページ | 相対リンクは解決しない。別ファイルに分けた素材は置けない。 |

ここから出る判断は 1 つです。**この経路の得意は「完成した映像を配る」ことではありません。**
同じ公式資料が挙げている用例が、ちょうどそれを示しています。「イージング曲線・持続時間・
遅延のスライダーを付けて、動かしながら値を試せるようにする」。
つまり**動きの値を決める台**としては素直に成立し、**映像ファイルを作って渡す器としては
既定で成立しません**。配る形が映像ファイルなら、書き出しは別の経路に置きます。

費用についても同じ資料が書いています。装飾のあるページは同じ内容を端末の文字で出すより
出力トークンを食い、主因は **data URI で埋め込んだラスタ画像**です。図は SVG か HTML/CSS を
優先し、要らない対話性は省きます。これは
[../token-drain-review/](../token-drain-review/) の点検対象に 1 項目足す話でもあります。

## 出す前に、機械で判定すること

止まっているものについて、この foundation には繰り返し同じ結論があります。
**描画された結果を目で見る検証は、見た目に出ない層の誤りを外す**（コントラスト、
ファイルの破損、欠けた関係）。動くものでは、目視で捕まらない側がさらに重くなります。
**見て気づかないまま、見た人を害することがある**からです。

1. **点滅**（`REF-171`）。規約は「1 秒のどの区間でも 3 回を超えて閃光しない、または
   閾値以下」。光過敏性発作の危険が根拠で、**好みの問題ではありません**。同じ文書は
   画面のキャプチャから解析する道具（PEAT）を名指ししています。つまり
   **これは機械が判定でき、人が目で数える必要はありません**。生成された動きに
   急な明滅や色の反転が入ったとき、目視の確認は通ります。
2. **停止できるか**（`REF-172`）。自動で始まり、5 秒を超えて続き、他の内容と並べて
   出す動きには、一時停止・停止・非表示の手段が要ります。動き自体がその活動に
   不可欠な場合は除外されます。**15 秒の解説アニメーションを資料やページに埋めるなら、
   3 条件すべてに当たります。** 単独で再生する動画として出すなら、並行表示の条件が
   外れます。**どちらで配るかを先に決めると、この判定が決まります。**
3. **動きを減らす設定**（`REF-174`）。利用者の OS 側に「不要な動きを減らす」設定があり、
   ページからは媒体特性として読めます（値は `no-preference` と `reduce`）。
   前庭系の障害への配慮が理由で、特に**拡大・縮小を伴う動き**が問題になると
   注意されています。`reduce` のときに動きを止める、または控えめにする分岐を
   最初から入れます。後から足すより安く済みます。
4. **音に対応する文字**（`REF-173`）。録画済みの音声を含む同期メディアには字幕が要ります。
   例外は、そのメディアがページ上の文章の代替であり、そう明示されている場合だけです。
   **ナレーションを付けると決めた時点で、字幕を作る作業が確定します。** 冒頭の
   「文字を併記しない方が効く」と衝突するので、字幕は用意した上で既定では
   出さない形にします。

これらは静止物の確認（溢れ、重なり、コントラスト、読める大きさ）を置き換えません。
**上に積むものです。**

## 入れる前に確かめること

1. その内容は、**変化の過程を見せる必要があるか**。静止した図とキャプションで足りるなら、
   伸びしろは小さい（`REF-170`）。
2. 説明を**音声に寄せ、同じ説明を文字で二重に出していないか**。出すなら、
   字幕として用意して既定では出さない形になっているか。
3. 正本は**コードか、映像ファイルか**。コードなら、動きは時刻や乱数ではなく
   フレーム番号から計算されているか。
4. 確認したのは**プレビューか、書き出した結果か**。録画で作ったなら、
   同じ入力から同じ映像が出ることは保証されていない。
5. **点滅の判定を機械に任せているか**。目視で代替していないか。
6. 自動で始まり 5 秒を超え、他の内容と並ぶなら、**止める手段があるか**。
7. **動きを減らす設定への分岐**が入っているか。
8. 共有の経路（1 枚の HTML ページか、映像ファイルか）を決めたか。
   ページで配るなら、外部参照・自前のダウンロード・大きさの制約に当たっていないか
   （`REF-168`）。
9. そもそも、作ったものを**人が本当に見るか**。
   [../comprehension-debt/](../comprehension-debt/) は、理解が保たれるのは差し出された
   説明を受け取る工程ではなく、人が不明点を問う工程だと記録しています。
   動くものは、止まっているものより**分かった気にさせる力が強い**分、この注意がよく効きます。
