# 新規プロジェクト雛形

```text
project/
├─ AGENTS.md            # 指示の正本。リポジトリ直下に置く
├─ docs/
│  └─ HANDOVER.md
├─ src/
└─ output/              # 追跡する成果物だけを置く
```

開始時に `AGENTS.md` へ目的、受け入れ条件、検証方法、変更禁止領域、参照設計書を記載します。特定のエージェントにしか意味のない指示が出てきたら、そのツールの入口ファイルを足して正本を取り込みます（[../agents-md/README.md](../agents-md/README.md)）。`docs/HANDOVER.md` には、目的と境界、現在の状態、次の手順、決定、環境、検証、成果物を残します。

認証情報、生データ、ローカル実行結果は追跡しません。必要なら `.gitignore` に最初から追加します。

## 開始時に書くものと、毎回走るもの

上の記載は**開始時に 1 回そろえるもの**です。同じ場所に機能を継ぎ足し続ける場合、これだけでは足りません。
繰り返し拡張を測った報告では、品質を意識させる指示は初期の状態を良くする一方、**回ごとの劣化の速さを
ほとんど変えません**（`REF-248`）。開始時の記載は床を上げる処置と数え、傾きを寝かせる処置は別に置きます。

そのため `AGENTS.md` の「検証方法」は、**過去の受入条件を含んだ 1 つのコマンド**にします。

- 回ごとの受入条件は、その回が終わったら**次の回以降も走り続ける検査**にする。文面のまま残さない。
- エージェントへ渡すのは、その積み上がった検査 1 つの実行方法。合否が返るものを渡すとエージェントが
  自分で閉じられますが、渡すものが「新しい分だけ」なら閉じるのも新しい分だけです（`REF-055`）。
- 変更したところだけの最小の検証は、**前の回の振る舞いについて何も言いません**。最小の検証は
  その回の確認であって、継ぎ足しの確認ではありません。
- 必ず走らせたいものは、指示文ではなく実行側が適用する層（hook・拒否規則）へ移します（`REF-055`）。

継ぎ足しで何が崩れるか、検査をどこに置くかは [../incremental-feature-drift/](../incremental-feature-drift/) にあります。
