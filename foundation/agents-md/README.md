# 指示ファイルの正本を AGENTS.md に置く

複数のコーディングエージェントを同じリポジトリで使うと、指示ファイルがツールごとに増えます。ここでは **ツール非依存の `AGENTS.md` を正本**とし、各ツールの固有ファイルはそのツールでしか意味のない内容だけを持つ薄い入口にする構成を扱います。雛形は [AGENTS.md.template](AGENTS.md.template) です。

## 置き場所の判断

| 内容 | 置き場所 |
| --- | --- |
| どのエージェントでも守ってほしい作業合意 | リポジトリ直下の `AGENTS.md`（正本） |
| そのツールにしか無い機能・設定の指示 | そのツールの指示ファイル（Claude Code なら `CLAUDE.md`） |
| 対象ファイルや用途が限定された方針 | そのツールの条件付き読み込み機構（Claude Code なら `.claude/rules/`） |
| 起動条件・入力・検証・終了条件がある反復作業 | skill などの呼び出し式の層 |
| 長い背景・設計理由 | リポジトリの文書 |

同じ事実を正本と入口の両方に書きません。入口には、正本を指す行と、そのツール固有の項目だけを残します。

## 各ツールが読む条件

下表は各製品の公式ドキュメントで確認した内容です（確認日 2026-10-06）。挙動は版で変わるため、導入時に各製品の正本を読み直します。

| ツール | 既定で読む指示ファイル | `AGENTS.md` を読ませる条件 | 正本 |
| --- | --- | --- | --- |
| Claude Code | `CLAUDE.md` 系（管理ポリシー・ユーザー・プロジェクト・ローカル） | 作業ディレクトリとその上位に `CLAUDE.md` / `.claude/CLAUDE.md` / `CLAUDE.local.md` が無ければ `AGENTS.md` を直接読む。両方読ませるには設定で明示する | `REF-001` |
| Codex | `AGENTS.md`（ネイティブ） | 既定で対応。ホームディレクトリの全体用と、プロジェクト直下から作業ディレクトリまでの各階層を結合する | `REF-006` |
| Gemini CLI | `GEMINI.md` | 設定で文脈ファイル名を配列指定でき、`AGENTS.md` を含められる | `REF-007` |

共通形式そのものの定義（リポジトリ直下に置く、入れ子では編集対象に近いファイルが優先、対応ツールの一覧）は `REF-005` にあります。ただし仕様側は必須項目を定めておらず、読み込み範囲・結合順・サイズ上限は各ツールの実装で異なります。**「AGENTS.md に対応している」を、同じ読み方をするという意味に取りません。**

### Claude Code で両方を読ませる

既定は「`CLAUDE.md` があればそちらだけ」です。`CLAUDE.md` と `AGENTS.md` を併置して両方読ませたい場合は、設定パネルの **Project instructions** を両方読む値にするか、ユーザー設定・管理設定の `pluginConfigs` に同じ値を書きます。この設定はプロジェクト設定とローカル設定では無視されるため、**リポジトリ側から強制できません**。チーム全員に同じ構成を期待する場合は、設定ではなく `CLAUDE.md` から `AGENTS.md` を取り込む形にします。

判定に数えるのはプロジェクト側の `CLAUDE.md` だけです。ユーザー個人の `~/.claude/CLAUDE.md`、組織の管理ポリシー、`.claude/rules/` は数に入らず、`AGENTS.md` と並んで読み込まれます。つまり、個人の共通設定を持ったまま、リポジトリ側は `AGENTS.md` 一本にできます。

### 取り込みと symlink

正本を一つにする方法は 2 つあります。

- **取り込み**: `CLAUDE.md` の先頭に正本を読み込む 1 行を置き、その下にツール固有の指示を書く。正本が先に読まれます。
- **symlink**: `CLAUDE.md` を `AGENTS.md` への symlink にする。ツール固有の内容を持てません。

**Windows を含むチームでは取り込みを選びます。** symlink の作成に管理者権限または開発者モードが要り、Git が設定次第で symlink を平文として取り出すため、clone 先で指示が 1 行のテキストに化けます。編集系ツールが symlink 越しの書き込みを拒む点も、取り込みを選ぶ理由になります。

取り込みは常時読み込みであり、起動時の context 消費は減りません（`ART-003`）。入口を薄くするのは正本を一つにするための手段であって、消費削減の手段ではありません。削減を狙うなら、呼び出し式の層へ移します。

## 入れ子にする前に（monorepo・大きなリポジトリ）

階層ごとに指示ファイルを置く構成では、正本を `AGENTS.md` にすると**読み込みの契機が狭くなります**。移す前に次を確認します。

| 事項 | 分かっていること | 根拠 |
| --- | --- | --- |
| 上位の入口ファイルが正本を打ち消す | Claude Code は、作業ディレクトリとその上位に `CLAUDE.md` 系があると `AGENTS.md` を読まない。判定は起動位置から上を見るため、どこか上に 1 つ残っているだけで `AGENTS.md` が読まれなくなる | `REF-001` |
| 下位の正本が読まれる契機 | 下位ディレクトリの `AGENTS.md` は、Claude がそのディレクトリのファイルを読み取り操作で開いたときに読み込まれる。そのディレクトリに `CLAUDE.md` 系があればそちらが優先される | `REF-001` |
| 下位の `CLAUDE.md` との差 | ファイルを明示的に指し示しただけでは、下位の `CLAUDE.md` は読み込まれるが下位の `AGENTS.md` は読み込まれない、という再現手順付きの未解決の報告がある。公式の差分表にはこの項目が載っていない | `REF-009` |
| 他ツールでは起きない差 | Codex は階層を起動時にまとめて連結するため、この種の遅延読み込みの差は生じない。読み方の差はツールごとに確かめる | `REF-006` |

このため、**入れ子が必要なリポジトリでは、`AGENTS.md` を置く各階層に、それを取り込むだけの薄い入口ファイルを併置する**のが安全です。入口ファイル側は読み込みの契機が広く、取り込みは展開されるため、正本を一つに保ったまま契機の差を埋められます。下位だけに置くと、そこから起動したときに上位の正本が読まれないため、上位の階層にも併置します。これは公開されている読み込み規則から導いた構成で、ここでは実機確認をしていません。導入時に、どのファイルが実際に読み込まれたかを確認してください。

階層化そのものの設計（どこで起動するか、根と各階層の役割分担、関わらない領域の除外、対象を絞るルールとの使い分け、階層ごとの skill、常時読み込みが限界に来たときの移し先）は `REF-008` に詳しくあります。ただし同資料は `CLAUDE.md` を前提に書かれているため、正本を `AGENTS.md` にする場合は上の差を重ねて読みます。

## 既存の環境から移す

1. 現在の指示ファイルから、ツールに依存しない作業合意だけを `AGENTS.md` へ移す。
2. 残った項目がそのツール固有かを確認する。固有でなければ正本へ戻す。
3. どのツールがどのファイルを実際に読んだかを、各ツールの読み込み状況表示で確認する。読まれた形跡を確認するまで「適用済み」と扱わない。
4. 以前の回避策（指示文で「`AGENTS.md` を読め」と書く、起動 hook で本文を流し込む等）を点検する。ネイティブ対応後は、同じ内容を二重に読ませる原因になります。
5. 指示は context であって強制ではありません。必ず止めたい操作は hook など仕組み側に置きます（`REF-001`）。

## 指示ファイル以外（skills・hooks・MCP）

正本を一つにできるのは指示ファイルだけではありません。ただし共有できる度合いは項目ごとに違い、共通形式の仕様（`REF-005`）はこれらを扱っていません。項目ごとに各製品の公式資料で確かめます。

| 項目 | 共有できるか | 確かめたこと |
| --- | --- | --- |
| skills | **置き場を共有できる** | 中身の形は両者とも `SKILL.md` を含むディレクトリで、`name` と `description` を持つ。Codex は作業ディレクトリ・その上位・リポジトリ根・利用者のホームの `.agents/skills` を順に探し、**symlink されたskillフォルダを辿る**（`REF-010`）。Claude Code が探すのは `.claude/skills` 系だけだが、**その下のskill名の項目を別の場所への symlink にできる**（`REF-002`） |
| hooks | 共有しない | 発火する出来事も書き方も製品ごとに違う。片方にしか無い仕組みを揃える意味がない |
| MCP | 設定形式が違う | 同じサーバーを指しても記述先と書式が異なる。共通化するなら変換が要る |
| 対象を絞るルール | 共有しない | 片方にしか対応する概念が無い場合がある。`ART-006` も、ルール本体は同期せず、どのファイルをいつ読むかだけを正本へ書き出す形にしている |

**skills の共有で確かめられた形**は、正本を `.agents/skills/<名前>/` に置き、`.claude/skills/<名前>` をその正本への symlink にする構成です。両製品の公開仕様が、この形のそれぞれの側を支えています。確かめていないのは `.claude/skills` ディレクトリごと symlink にする形で、公開資料が述べているのは skill 名の項目を symlink にできる、という範囲です。Windows を含む環境では symlink 自体が使えないことがあるため、指示ファイルと同じく、まず取り込みや複製で代替できないかを検討します。

Claude Code 側だけで skills・subagent・hook・MCP をひとまとまりにして版を付け配布する仕組みもあります（`REF-011`）。チームへ配る・版を管理するという目的にはこちらが向きますが、他のエージェントとは共有できず、有効にしている間は使わない回でも名前と説明が毎回の context を占めます。共有が目的なら置き場の共有、配布と版管理が目的ならまとめて配る仕組み、と目的で選び分けます。

## 無理に同期しない

ツールごとにプロンプトの流儀や対応機能が違うため、全項目の同期は二重管理を増やします（`ART-006`）。共有できる事実を正本へ寄せ、固有の実行手順は各ツール側に残す切り分けを保ちます。
