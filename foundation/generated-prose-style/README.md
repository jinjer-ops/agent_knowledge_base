# 書かせた文章を、検出するのか書き直させるのか

**この構成はこの環境で運用していません。** 根拠は公開された研究と、公開されている道具の
一次情報です。ここに書いたのは判断の型で、状態は `experiment` です。

起動条件は「**エージェントに書かせた文章が「AI っぽい」「読みにくい」と感じて、
直す仕組みを入れようとしたとき**」です。

隣の手引きとの違いは対象です。[../review-design/](../review-design/) はコードの指摘を
どの層に置くかで、**指摘を下の層へ移してよいかの判定基準はそちらにあります**。ここは対象が
文章で、固有なのは **「書き直させる」側に測られた代償がある**ことです。コードの整形と違い、
文章の書き直しは消える情報があります。

## 「AI っぽさ」は気のせいではない。ただし測られたのは英語

査読済みの計量研究が、2010〜2024 年の生物医学論文の抄録 1,500 万件以上で語彙の変化を追い、
**特定の語の頻度が 2024 年に急増した**ことを示しています（`REF-088`）。増えたのは内容語だけでなく、
半分近くは文体の語でした。著者らはこの過剰分から、2024 年の抄録の**少なくとも 13.5%** が
LLM を通ったと推定しています。

ここから採れるのは「**定型句の偏りは機械的に測れる**」という形だけです。測られたのは
英語の、しかも学術抄録という特定の文種です。同じ語彙表を日本語へ持ってくる根拠にはなりません。

## 書き直させると、内容は残り、文体が縮む

これが、この手引きで最も効く測定です（`REF-089`、査読済み / Nature Human Behaviour 2026）。

| 測定 | 条件 | 観測 |
| --- | --- | --- |
| 3 つの研究・7 つのデータセット | 88 万件以上のテキスト、複数のモデルで書き直し | **文章の複雑さの分散が 21〜50% 減少**（統計的に有意） |
| 書き手の属性を推定する分類器 | LLM による書き直しの前後で比較 | 書き直した後は精度が落ちる。**内容は保たれるが、個人の手がかりが薄れる** |

つまり、LLM に推敲させる工程は「AI 臭さ」を消すのではなく、**別の平均へ寄せ直す**動きをします。
目的が「読みやすくする」なら効くかもしれませんが、「AI っぽさを消す」が目的なら、
手段と目的が逆を向いている可能性を先に確かめる必要があります。

この違いは、入れる仕組みを選ぶときにそのまま効きます。

| 仕組み | 何をするか | 文体への影響 |
| --- | --- | --- |
| **指摘する**（linter） | 該当箇所を挙げる。直すかは書き手が決める | 書き手が選んだ分だけ動く |
| **書き直させる**（LLM の推敲） | 文を作り直して返す | 上の測定が当てはまる。分散が縮む方向 |

既定の最終工程に書き直しを置くと、後者が全文に掛かります。**誰が何を捨てたかが残りません。**

## 書き直させる道具を入れるなら

書き直す側の道具は実際に出回っていて、日本語でもエージェントから呼び出す形のものがあります
（`ART-039`、`REF-092`）。非生物主語を人に戻す、比喩動詞を具体的な動作に置き換える、
名詞の連続をほどいて述語を復元する、といった変換を並べた作りです。入れるかどうかを決める前に、
次の 3 点を確かめます。

### 1. 読みやすくする書き直しは、事実を壊す方向に誤る

査読済みの研究（`REF-093`、ACL 2022）が、文章を平易にする自動変換の出力を誤りの種類ごとに
分類して調べ、**参照データと最先端モデルの出力の両方に誤りが頻繁に現れる**こと、そして
**既存の自動評価指標がそれを捕まえていない**ことを示しています。誤りは削除の側にも挿入の側にも
出ます。著者らは、誤って平易化された文章は**平易化されていない文章より悪くなりうる**と述べています。

対象は英語の、主に医学文献の平易化です。日本語の文体の書き直しに割合をそのまま移すことはできません。
採るのは向きと、**何を見れば気付けるか**です。出力を読んで自然かどうかを見ても、
消えた条件や入れ替わった主体には気付けません。**前後の差分を見られる形**にしておくことが条件になります。

### 2. 書き直した本人に合否を判定させない

書き直す道具は、同じモデルに「直したから良くなった」と言わせがちです。これは測られています
（`REF-094`、NeurIPS 2024）。**評価役のモデルは自分の出力に高い点を付け**、人の評価者が同等と
判断したものでも差が付きます。同じ研究は、モデルが自分の出力をそれと認識できる度合いと、
自己優遇の強さが対応することも示しています。

道具から独立した研究は、その裏返しも言っています。生成したものを同じモデルに直させる構成は
**自分で良いフィードバックを作れるかが律速**で、質の高いフィードバックを外から入れると大きく改善します
（`REF-081`）。したがって、合否は**別の決定論的な検査**に出します。

ここで、[../review-design/](../review-design/) と同じ結論に合流します。注目に値するのは、
公開されている日本語の道具が 3 つとも、**独立に同じ形へ到達している**ことです。

| 道具 | 形 |
| --- | --- |
| 指摘する側（`REF-087`） | 規則ごとに人の文書での誤検知を数え、未測定の規則は既定で無効 |
| 書き直す側（`REF-092`、`ART-039`） | skill の指示文に頼らず、検査スクリプトの実行を必須にする |
| もう一つの書き直す側（`REF-098`） | 形態素解析で**検出は機械、判断は人**。コーパスと回帰チェックを同梱 |

2 つ目の作者が挙げている理由は「モデルは自己チェックで甘く評価する」で、上の測定と一致します。
3 つ目は、**何を機械に任せないか**まで明示しています。語順や読点のような領域は機械的な判定が
難しいとして、目視の併用を勧めています。**機械に出す範囲を狭く決めてある**という点が共通です。

### 3. 「指摘なし」は品質の保証ではない

書き直す側の道具の README 自身が、**検査が通ったことは設定した規則に触れなかったことを示すだけで、
文章の自然さや意味の保持を保証しない**と書いています（`REF-092`）。これは道具の弱点ではなく、
正しい限界の書き方です。読む側がこれを「品質が確認できた」と受け取ると、1 と 2 の対策が
そこで止まります。

### 4. どれを使うかは、比べる前に軸で決まる

同じ用途の道具が複数あります。公開されている比較（`ART-040`）を読むと、違いが並ぶのは
**どこまで直すか**という一本の軸でした。

| 直す範囲 | 何が起きるか |
| --- | --- |
| 指摘だけして直さない | 書き手が選んだ分だけ動く |
| 文体と構成を残して語句を直す | 元の調子は残る |
| 見出しと段落から組み直す | 文章の並びが変わる |
| 文体そのものを統一する | 書き手の調子は残らない |

**これは好みではなく、入れる前に決められる設計の選択です。** 自分の文書で何を保持したいかを
先に決めれば、候補はここでほとんど絞れます。

### 5. 1 本を 1 回ずつ流して比べても、順位は出ない

同じ比較は、比べ方の難しさもそのまま見せています。対象は原文 1 本、各道具 1 回の実行、
評価は著者 1 人の印象で、**意味が保たれたかは確認されていません**。著者自身が
「出力には揺れがあるので優劣を決める検証ではない」と書いており、これは限界の表明というより
**読み方の指定**として扱うのが正確です。検証に使われた版と、その時点の最新版も違っていました。

評価を実験として扱う方法は整理されています（`REF-097`）。評価の問いは観測されていない母集団から
引かれた標本であり、**点推定だけを報告するのではなく不確かさを付ける**、2 条件の差を測る、
実験を計画する、という手順が置けます。**1 本 1 回は、差を測る土俵にまだ乗っていません。**

比べる単位を**編集**に落とす方法もあります（`REF-096`、査読済み / EMNLP 2023）。言語学的に
定義した 21 種の編集型で、平易化の**成功と失敗を編集ごとに**分類する枠組みで、
840 件の書き直しについて 19,000 件の編集注釈を集めています。報告されている知見のうち、
この手引きに効くのは次の 2 つです。

- 微調整したモデル、指示で動かしたモデル、人では、**採る編集の分布が違う**
- 当時の大規模モデルは**人より質の高い編集を多く行う一方、誤りも頻繁**だった

「全体として良くなったか」ではなく「どの編集が成功し、どれが失敗したか」を見ると、
前者では隠れる失敗が出てきます。自分で比べるときも、**出力同士を見比べる前に、編集を数える**
形にできます。

最低限の条件はこうなります。

- 文書を複数本、各道具を複数回。1 本 1 回の結果を順位にしない
- **意味が保たれたかを項目に入れる**（1 の理由）
- 道具の**版を記録して固定する**。更新が速い領域です
- 判定者を道具自身にしない（2 の理由）

### 読みやすいとは何か、を先に決める

「AI っぽさを消す」は手段であって目的ではありません。目的の側には、国際的に合意された言い方が
あります。PLAIN が公開している説明によれば、平易な言葉遣いの国際規格は plain language を
**「意図した読み手が、必要なものを見つけ、見つけたものを理解し、その情報を使える」**ほどに
言葉・構造・設計が明確な伝達と定義しています（`REF-095`）。

この定義は、判定の位置を**書き手の感想から読み手の達成へ**動かします。語彙の表を増やす前に、
自分の文書で「見つかる・分かる・使える」のどれが壊れているのかを決めると、
そもそも書き直しが要るのかどうかから判断できます。

## 「AI っぽい」を、文書や人の判定に使わない

表層の特徴から「AI が書いたか」を当てる試みには、査読済みの反証があります（`REF-090`）。
複数の検出器が、**非母語話者の英作文を一貫して AI 生成と誤判定**しました。著者らは原因として、
語彙や構文の幅が狭い文章は（書き手が誰であれ）モデルにとって予測しやすく、
その予測しやすさが判定の根拠にされていることを挙げ、**評価や教育の場面での使用に警告**しています。

採るべき帰結は 2 つです。

- **検査の出力を、人や文書の「AI 判定」として使わない。** 使えるのは、自分が今書いたものに対する
  指摘までです
- **型に沿った文章ほど引っかかる。** 手順書、定型の報告、ですます調で統一した説明文は、
  人が書いても特徴が一致しえます。誤検知はランダムではなく、特定の文種に偏って出ます

## 既定で有効にしてよい検査の条件

上の偏りがあるので、「それらしいルール」を既定で有効にすると、ノイズの置き場所が変わるだけです。
**移してよいかの判定基準は [../review-design/](../review-design/) にあります**（`REF-075`）。
中心は誤検知の数え方で、**指摘を見た人が何も行動しなかったなら、技術的に正しくても誤検知として
数えます**。文章の検査でも定義は同じ向きに効きます。

この条件を実際に満たそうとしている例が、日本語向けの検査器の一次情報にあります（`REF-087`）。
その規則一覧は、ルールごとに**人が書いた文書での誤検知を実際に数えた記録**を持ち、
**数えていないルールは既定で無効**にして、実験扱いの区分に置いています。
見送られたルールの記録もあり、ある閾値は実文書の過半に反応したため採用されていません。

評価しているのは道具そのものではなく、**この形**です。

- 既定で有効にするルールには、人の文書での誤検知を数えた記録がある
- 数えていないものは既定で無効、という明示の区分がある
- **何を指摘しないかを決めてある**

新しい検査を自分で書くときも、入れるかを判断するときも、この 3 つが揃っているかを見れば足ります。

## 二つのレーンを混ぜない

「AI っぽい」と「読みにくい」は別の問題です。

| レーン | 例 | 現状 |
| --- | --- | --- |
| 読みやすさ | 一文の長さ、読点の数、漢字の連続、文体の統一、二重否定 | **成熟した既存の道具がある**（`REF-091`） |
| 定型句の偏り | 結論の押し付け、空疎な接続、空虚な形容、文長の単調さ | 新しい領域で、道具も若い |

読みやすさの側は、日本語の技術文書向けに 24 ルールのプリセットが公開されており、
半年ごとの安定版が出ています（`REF-091`）。こちらが欲しいだけなら、新しい道具を入れる話には
なりません。**自分が困っているのがどちらのレーンかを先に決める**と、選択肢がほとんど自動的に決まります。

## 置き場所

- **常時掛けたい検査**は、指示ファイルの文章ではなく実行される仕組みに置きます。
  指示ファイルは助言で、hook は決定論的に動きます（`REF-020`）
- **常時読み込みの層に禁止語リストを置かない。** 誤検知が偏って出る（`REF-090`）以上、
  検査でも計測でもない注意書きが増えるだけになります
- **書き直しを自動の最終工程にしない。** 入れるなら、前後の文を残して**何が変わったかを
  人が見られる形**にします。消えるのは文体の区別だけではなく（`REF-089`）、
  条件や主体といった内容も落ちうるからです（`REF-093`）

## 限界

- `REF-088` が測ったのは英語の生物医学抄録です。語の一覧も推定値も日本語には移せません。
  採ったのは「定型句の偏りは測れる」という形だけです。
- `REF-089` の 21〜50% は、提示されたデータセットとモデルに固有の値です。対象は主に英語で、
  日本語の文書で同じ幅になる根拠はありません。採ったのは**向き**（書き直しは分散を縮める）です。
- `REF-090` は 2023 年の検出器を対象にしています。要旨に具体的な誤判定率は無く、
  ここで採ったのは「表層特徴による判定は特定の書き手に偏って外れる」という一点だけです。
  その後のモデルで検出がさらに難しくなったという主張も見かけますが、独立した測定を確認していないため採っていません。
- `REF-087` はこの環境で動かしていません。公開されている規則一覧と README を読んだだけで、
  導入も配置も勧めていません。入口になった記事（`ART-038`）とリポジトリでルール数と既定数が
  食い違っており、版が動いている最中の道具です。
- `REF-091` も導入していません。確認したのは、公開されているルールの内容と更新の周期だけです。
- `REF-093` が測ったのは英語の、主に医学文献の平易化です。誤りの分類と「既存の指標が捕まえない」
  という結論を採り、割合は移していません。2022 年時点のモデルを含む点も含めて読みます。
- `REF-094` が測っているのは評価役としてのモデルの振る舞いで、文章の推敲に限った測定ではありません。
  採ったのは「自分の出力に甘い」という向きだけです。
- `REF-092` と `ART-039` はこの環境で動かしていません。記事側の定量値（コーパスでの誤検出率の低下）は
  **検出器の精度**であって書き直し後の品質ではなく、書き直しの側は例示と利用者の感想だけなので、
  品質の根拠としては使っていません。利用の広がりも有効性の証拠として扱っていません。
- `REF-095` について、規格本体は有償で読んでいません。確認したのは PLAIN の解説ページに
  引用された定義と、規格の名称・発行年だけです。規格が定める原則の構成までは確かめていません。
- `ART-040` は原文 1 本・各道具 1 回・評価者 1 人の記録で、意味の保持は確認されていません。
  採ったのは**直す範囲という軸**と、比べ方の難しさだけで、どの道具が良いかは採っていません。
  検証された版と現在の版も違います。
- `REF-096` が対象にしているのは英語の平易化で、2023 年時点のモデルを含みます。採ったのは
  **編集単位で成功と失敗を分ける**という枠組みと上の 2 つの知見だけで、注釈の体系も指標も
  そのまま持ち込んでいません。
- `REF-097` は査読前で、確認したのは要旨の範囲です。採ったのは「評価は実験であり、点推定だけでは
  差を主張できない」という向きで、具体的な統計手法までは確かめていません。
- `REF-098` はこの環境で動かしていません。確認したのは公開されている構成と、作者自身が挙げている
  適用範囲の限界だけです。導入は勧めていません。
- この手引き自体が、この環境で検査を回して書かれたものではありません。入れるなら、
  まず**既定で有効にするルールごとに、自分の過去の文書で誤検知を数える**ところから始めます。
