# 書かせた文章を、検出するのか書き直させるのか

**この構成はこの環境で運用していません。** 根拠は公開された研究と、公開されている道具の
一次情報です。ここに書いたのは判断の型で、状態は `experiment` です。

起動条件は「**エージェントに書かせた文章が「AI っぽい」「読みにくい」と感じて、
直す仕組みを入れようとしたとき**」です。

隣の手引きとの違いは対象です。[../review-design/](../review-design/) はコードの指摘を
どの層に置くかで、**指摘を下の層へ移してよいかの判定基準はそちらにあります**。ここは対象が
文章で、固有なのは **「書き直させる」側に測られた代償がある**ことです。コードの整形と違い、
文章の書き直しは消える情報があります。

## 「AI っぽさ」は気のせいではない。ただし測られたのは英語

査読済みの計量研究が、2010〜2024 年の生物医学論文の抄録 1,500 万件以上で語彙の変化を追い、
**特定の語の頻度が 2024 年に急増した**ことを示しています（`REF-088`）。増えたのは内容語だけでなく、
半分近くは文体の語でした。著者らはこの過剰分から、2024 年の抄録の**少なくとも 13.5%** が
LLM を通ったと推定しています。

ここから採れるのは「**定型句の偏りは機械的に測れる**」という形だけです。測られたのは
英語の、しかも学術抄録という特定の文種です。同じ語彙表を日本語へ持ってくる根拠にはなりません。

## 書き直させると、内容は残り、文体が縮む

これが、この手引きで最も効く測定です（`REF-089`、査読済み / Nature Human Behaviour 2026）。

| 測定 | 条件 | 観測 |
| --- | --- | --- |
| 3 つの研究・7 つのデータセット | 88 万件以上のテキスト、複数のモデルで書き直し | **文章の複雑さの分散が 21〜50% 減少**（統計的に有意） |
| 書き手の属性を推定する分類器 | LLM による書き直しの前後で比較 | 書き直した後は精度が落ちる。**内容は保たれるが、個人の手がかりが薄れる** |

つまり、LLM に推敲させる工程は「AI 臭さ」を消すのではなく、**別の平均へ寄せ直す**動きをします。
目的が「読みやすくする」なら効くかもしれませんが、「AI っぽさを消す」が目的なら、
手段と目的が逆を向いている可能性を先に確かめる必要があります。

この違いは、入れる仕組みを選ぶときにそのまま効きます。

| 仕組み | 何をするか | 文体への影響 |
| --- | --- | --- |
| **指摘する**（linter） | 該当箇所を挙げる。直すかは書き手が決める | 書き手が選んだ分だけ動く |
| **書き直させる**（LLM の推敲） | 文を作り直して返す | 上の測定が当てはまる。分散が縮む方向 |

既定の最終工程に書き直しを置くと、後者が全文に掛かります。**誰が何を捨てたかが残りません。**

## 「AI っぽい」を、文書や人の判定に使わない

表層の特徴から「AI が書いたか」を当てる試みには、査読済みの反証があります（`REF-090`）。
複数の検出器が、**非母語話者の英作文を一貫して AI 生成と誤判定**しました。著者らは原因として、
語彙や構文の幅が狭い文章は（書き手が誰であれ）モデルにとって予測しやすく、
その予測しやすさが判定の根拠にされていることを挙げ、**評価や教育の場面での使用に警告**しています。

採るべき帰結は 2 つです。

- **検査の出力を、人や文書の「AI 判定」として使わない。** 使えるのは、自分が今書いたものに対する
  指摘までです
- **型に沿った文章ほど引っかかる。** 手順書、定型の報告、ですます調で統一した説明文は、
  人が書いても特徴が一致しえます。誤検知はランダムではなく、特定の文種に偏って出ます

## 既定で有効にしてよい検査の条件

上の偏りがあるので、「それらしいルール」を既定で有効にすると、ノイズの置き場所が変わるだけです。
**移してよいかの判定基準は [../review-design/](../review-design/) にあります**（`REF-075`）。
中心は誤検知の数え方で、**指摘を見た人が何も行動しなかったなら、技術的に正しくても誤検知として
数えます**。文章の検査でも定義は同じ向きに効きます。

この条件を実際に満たそうとしている例が、日本語向けの検査器の一次情報にあります（`REF-087`）。
その規則一覧は、ルールごとに**人が書いた文書での誤検知を実際に数えた記録**を持ち、
**数えていないルールは既定で無効**にして、実験扱いの区分に置いています。
見送られたルールの記録もあり、ある閾値は実文書の過半に反応したため採用されていません。

評価しているのは道具そのものではなく、**この形**です。

- 既定で有効にするルールには、人の文書での誤検知を数えた記録がある
- 数えていないものは既定で無効、という明示の区分がある
- **何を指摘しないかを決めてある**

新しい検査を自分で書くときも、入れるかを判断するときも、この 3 つが揃っているかを見れば足ります。

## 二つのレーンを混ぜない

「AI っぽい」と「読みにくい」は別の問題です。

| レーン | 例 | 現状 |
| --- | --- | --- |
| 読みやすさ | 一文の長さ、読点の数、漢字の連続、文体の統一、二重否定 | **成熟した既存の道具がある**（`REF-091`） |
| 定型句の偏り | 結論の押し付け、空疎な接続、空虚な形容、文長の単調さ | 新しい領域で、道具も若い |

読みやすさの側は、日本語の技術文書向けに 24 ルールのプリセットが公開されており、
半年ごとの安定版が出ています（`REF-091`）。こちらが欲しいだけなら、新しい道具を入れる話には
なりません。**自分が困っているのがどちらのレーンかを先に決める**と、選択肢がほとんど自動的に決まります。

## 置き場所

- **常時掛けたい検査**は、指示ファイルの文章ではなく実行される仕組みに置きます。
  指示ファイルは助言で、hook は決定論的に動きます（`REF-020`）
- **常時読み込みの層に禁止語リストを置かない。** 誤検知が偏って出る（`REF-090`）以上、
  検査でも計測でもない注意書きが増えるだけになります
- **書き直しを自動の最終工程にしない。** 入れるなら、前後の文を残して**何が変わったかを
  人が見られる形**にします。上の測定が示すのは、消えるのが内容ではなく区別だということです

## 限界

- `REF-088` が測ったのは英語の生物医学抄録です。語の一覧も推定値も日本語には移せません。
  採ったのは「定型句の偏りは測れる」という形だけです。
- `REF-089` の 21〜50% は、提示されたデータセットとモデルに固有の値です。対象は主に英語で、
  日本語の文書で同じ幅になる根拠はありません。採ったのは**向き**（書き直しは分散を縮める）です。
- `REF-090` は 2023 年の検出器を対象にしています。要旨に具体的な誤判定率は無く、
  ここで採ったのは「表層特徴による判定は特定の書き手に偏って外れる」という一点だけです。
  その後のモデルで検出がさらに難しくなったという主張も見かけますが、独立した測定を確認していないため採っていません。
- `REF-087` はこの環境で動かしていません。公開されている規則一覧と README を読んだだけで、
  導入も配置も勧めていません。入口になった記事（`ART-038`）とリポジトリでルール数と既定数が
  食い違っており、版が動いている最中の道具です。
- `REF-091` も導入していません。確認したのは、公開されているルールの内容と更新の周期だけです。
- この手引き自体が、この環境で検査を回して書かれたものではありません。入れるなら、
  まず**既定で有効にするルールごとに、自分の過去の文書で誤検知を数える**ところから始めます。
