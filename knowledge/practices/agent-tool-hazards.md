# エージェントの道具で、静かに壊れること

エラーにならずに中身が変わる、止めたつもりで止まっていない、という壊れ方です。Windows 上の Claude Code（Bash ツールは Git Bash）で起きたものが中心で、出どころは 2026-07〜10 の運用の記録です。ファイルの符号化・改行・クラウド同期は [../../foundation/windows-file-hazards/README.md](../../foundation/windows-file-hazards/README.md) にあります。

| 何が起きるか | どうするか |
| --- | --- |
| Bash ツールの heredoc（`python - <<'PY'`）に流したコードの `\n` が、引用符付きの区切りでも実際の改行に変わり、Python の文字列が壊れる | バックスラッシュを含むコードは heredoc で渡さない。ファイルに書いてから `python <path>` で実行する。改行の書き込みには `print(value, file=handle)` を使う |
| ツール呼び出しの本文で日本語を `\uXXXX` と書くと、見た目の似た別の字に変わり、エラーにならずに公開される（懸念→憬念、暫定→暂定、「二」が部首の字になる） | 本文は素の UTF-8 で書き、正確さが要る本文はファイルから流す。公開したら読み戻し、正しい語で検索して照合する。部首（U+2E80〜2FDF）と互換漢字（U+F900〜FAFF）の範囲は機械で拾える。仮名の入れ替わりは拾えない |
| Windows で裏の実行を止めても、止まるのは外側のシェルだけで、子の python は最後まで走る | 止めたら `Get-CimInstance Win32_Process -Filter "Name='python.exe'"` でコマンド行を見て、残りを `Stop-Process` で止めてから錠や出力に触る。費用のかかる処理は事例ごとに区切って流す |
| 許可の規則に決してマッチしないコマンドの形がある。規則は `&&`・`;`・`\|` で分けた各部分がそれぞれマッチする必要があり、先頭のコマンド名で前方一致する。`$var = ...;` で始まる PowerShell の複数文や、`export X=1 &&`・`$env:X=...;` の接頭辞は、どの規則にも当たらない | ロジックはスクリプトに書いて `python script.py` で動かす。文字コードの接頭辞は付けず、設定の環境変数（`PYTHONUTF8=1` など）で揃える |
| Git Bash から gcloud に `/` で始まる値を渡すと `C:/Program Files/Git/…` に書き換わり、そのまま設定に入る。デプロイは成功し、利用者が来て初めて 403 として表に出る | 書き換えを全部止める（`MSYS_NO_PATHCONV=1`）と gcloud の起動自体が壊れる。該当する引数の先頭だけを `MSYS2_ARG_CONV_EXCL` で除外し、載せた後に値を読み直す |
| Claude Code の指示ファイルで `@C:\Users\…\AGENTS.md` のように `\` 区切りの Windows のパスで読み込みを書くと、読み込まれない。エラーは出ず、その行だけが文として残る | `@C:/Users/…/AGENTS.md` のように `/` で区切るか、`@~/…` と書く。書いたら、読み込んだ先の文を知っているかをエージェントに聞いて確かめる |
| VSCode 拡張の入力欄で `! <コマンド>` と打っても実行されず、文として届く | 利用者に操作を頼むときは「このコマンドを貼って送ってください」か「ターミナルで実行してください」と案内する |
| 自動モードの安全確認が、会話で許可された大きなマージや権限の付与を止める | 別のコマンドで同じ結果を狙わない（止めているのは結果である）。止められたことと理由を利用者に伝え、明示の指示を受けてから打ち直すか、操作を利用者に渡す |
| 検査の出力を grep で絞って `&&` でコミットに繋ぐと、終了コードが grep のものになり、検査が止めるべき変更でもコミットが走る | 検査とコミットを別のコマンドにする（[../../skills/git-publish/SKILL.md](../../skills/git-publish/SKILL.md)） |

## 共通する見方

- どれも**成功の表示が出る**。エラーを待たず、結果（書かれた値・公開された文字・残った処理）を読み直して確かめる。
- 原因が道具の側にあると気づかないと、自分の書き方の誤りと読んで直し続ける。同じ形で 2 回壊れたら、道具の側を疑う。
