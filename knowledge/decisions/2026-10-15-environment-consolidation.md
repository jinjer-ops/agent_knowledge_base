# 入れる環境を、このリポジトリの 1 か所に集める

## 決めたこと

端末に入れる共通の環境（AGENTS.md・skill・Claude Code の subagent）の正本を、このリポジトリの `environment/` と `skills/` に置く。各エージェントの置き場は、この正本へのリンク（指示ファイルは読み込みか連結）にする。組織・案件・個人に固有のものは、このリポジトリに置かず、各自の手元の層に残す。

## そうする前の状態

同じ環境が 3 つのリポジトリと 2 つの実行環境に重なっていた。

| 場所 | 中身 | 問題 |
| --- | --- | --- |
| 公開の基盤リポジトリ | AGENTS.md の本文と skill 10 本 | 手元の Claude Code が直接読み込んでいたが、持ち主は写しだと思っていた。skill 1 本は main に入っていなかった |
| 非公開の個人のバックアップ | 設定・記憶・skill・このリポジトリの古い写しの全部 | 5 週間更新が止まり、何からも読まれていなかった |
| このリポジトリ | 環境の作り方のガイドと出典 | 入れる環境そのものが無く、出典から環境へ辿れなかった |
| 各エージェントの skill の置き場 | skill のコピー | 4 本が基盤リポジトリと中身がずれていた。Codex の置き場は公式の文書にない旧い場所だった |

## 採った形と理由

- **このリポジトリに集める。** 出典台帳から各ガイドへ、ガイドから環境へ辿れるので、「環境を真似できて、その環境を作るに至った出典も見られる」が 1 つのリポジトリで成り立つ。
- **リンクにする。** コピーはずれる。リンクなら、手元で直した skill がそのままこのリポジトリの変更として見え、共有の手順（PR と公開前の検査）に乗る。
- **AGENTS.md は `environment/` に置き、リポジトリの根には置かない。** 根に置くと、このリポジトリで作業するエージェント自身の指示と混ざる。
- **AGENTS.md は Knowledge Inbox の自動マージの対象に入れない。** 常に効く指示が、レビューなしで書き換わらないようにする。
- **Codex の skill の置き場は `~/.agents/skills` にする。** 公式の文書に載っている利用者全体の置き場で、リンクを辿ることも明記されている。

## 採らなかった案

| 案 | 採らなかった理由 |
| --- | --- |
| 公開の基盤リポジトリを正本のまま残し、ここから参照する | 環境と出典が別のリポジトリに分かれ、辿れない。重なりも残る |
| 個人のバックアップを全部入りのまま更新し続ける | 共有する分が 2 か所に重なる。持ち主が、共有しない層のバックアップは不要と判断した |
| 共有しない層（社内・個人）を CLAUDE.md だけに置く | Codex も社内の作業でその層を読んでいる。CLAUDE.md だけにすると Codex が読めなくなるので、両方から読める手元のファイルにした |
| 公開前の検査を強制する PreToolUse フックを同梱する | コマンドの文面を読む見張りは書き方を尽くせない（同じ目的の見張りの監査で、回すたびに新しい抜けが出た）。保証は git の pre-push とサーバー側のブランチ保護に置く |
| コピーで配る配備の仕組み（指紋を固定して配り、突き合わせる） | リンクにしたので、ずれを突き合わせる仕組みが要らない。今の状態は導入スクリプトの `-Check` で見る |

## 一緒に変えたこと

- 公開の手順の skill が 3 本重なっていたので、英語の汎用版を外し、機械検査を持つ `git-publish` を主にした。`repository-publish` は Knowledge Inbox の成果の台帳に載っているので、まとめるのは台帳に別名を記録するときにする。
- 別のセッションの一覧を読む skill は、持ち主が「自分だけで使う」と決めていたので含めない。
- 運用の記憶から、組織に固有でない教訓を [../practices/](../practices/) と AGENTS.md・skill に移した。

## 見直す条件

- エージェントが skill の置き場や指示ファイルの読み方を変えたとき（各ガイドの確認日を見る）。
- 共有しない層を複数の端末で使う必要が出たとき（手元だけの今の形では足りない）。
