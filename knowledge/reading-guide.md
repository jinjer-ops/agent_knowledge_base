# 読書ガイド

人が読むための入口です。[sources/articles.yml](sources/articles.yml) に登録した URL について、「何が書かれているか」「自分たちにとっての示唆」「現在の扱い」を1件ずつ日本語でたどれるようにしています。

機械処理用の出典台帳は [sources/articles.yml](sources/articles.yml) が正本です。このガイドは台帳を置き換えるものではなく、同じ source ID を人向けに説明する層です。status は台帳の値をそのまま反映します。関連文書の全一覧は台帳の `derived` を正本とします。

## このガイドの読み方

- **カードは source ID ごとに1つ**です。台帳の全 ID を扱います。
- **現在の扱い**は、いま手元に何が残っているかで決まります。記事の質や正しさの評価ではありません。

| 扱い | 条件 |
| --- | --- |
| `adopted` | 検証済みの採用・実験の裏付け（decision、practice、guidance）が現存する。記事の全主張を採用したという意味ではない |
| `experiment` | 現存する experiment charter があり、比較・検証の枠がいま読める |
| `reference` | 上のどちらでもない。読む価値のある出典として保持している。推奨でも導入済みでもない |

- **採用・実験の裏付け** は、`adopted` / `experiment` の status を支える現存文書です（decision、practice、guidance、または experiment charter）。`reference` の source には存在しないため「該当なし」と書きます。
- **関連文書の全一覧はこのガイドには載せません。** source ID を宣言している現存文書の完全な逆引きは、台帳 [sources/articles.yml](sources/articles.yml) の `derived` を見てください。`derived` は関連文書の索引であり、status の根拠ではありません。
- **何が書かれているか**は、URL を読めた場合だけ書いています。本文を確認できなかった場合は「本文未確認」と明記し、内容を推測しません。
- 記事本文・画像・長文引用は転載しません。要約はいずれも独自の記述です。

### ART-003 CLAUDE.md を3層に分けた実測記録

- **URL**: <https://zenn.dev/pepabo/articles/claude-code-rules-skills-split>
- **記事種別**: 技術記事（実装記録・実測値あり）
- **現在の扱い**: `adopted`（2026-10-06 に再読して内容と数字の扱いを更新）
- **何が書かれているか**: 2000行近くまで膨れた `CLAUDE.md` を、入口となる本体・常時効かせる rules・呼び出し時だけ読み込む skills の3層へ分割した記録。置き場所を決めるための分岐（全作業の前提か／繰り返し効く制約か／明示的に呼ぶ手順か）を示し、ホスト別の出し分けを dotfile 管理ツールの条件分岐で行う運用も載せる。試行錯誤の記録が厚く、既製の枠組みを丸ごと取り込んで未使用分まで載せていたこと、似た skill を 24 個作って重複したこと、良い例と悪い例を全ルールに入れて倍に膨らんだこと（外しても精度は変わらなかった）、rules を版管理の外に置いて複数の計算機でずれたことを、原因と対処付きで挙げている。トークンは `tiktoken` でファイルを数えており、本体 1,689・取り込んだ枠組み 8,170・rules 15本 9,373・skills 40本 95,615 と内訳が出ている。見出しの「83%」は、この合計 114,847 から起動時に読み込まれる 19,232 を引いた割合である。
- **得られる示唆**: 置き場所を決める基準は「いつ読み込まれるか」であって、ファイル数ではない。分割しても常時読み込みなら消費は変わらないため、削減を狙うなら呼び出し式の層へ移す必要がある。失敗の記録は公式資料には出てこない部分で、ここが本体の価値である。**一方、見出しの割合は前後比較ではない。** 分母は書いた文章の総量で、その 95,615 は skills の本文、すなわち呼び出し式の層に置かれている分である。記事自身の経過からしても、この分量がもともと入口ファイルに載っていたわけではない。さらに 19,232 には、常時読まれる skill の名前と説明（40本分）が入っていない（`REF-002`、`REF-017`）。したがってこの数字は自分の環境の期待値にしない。測るなら、製品が出す実際の内訳を前と後で比べる（`REF-017`）。
- **再読で確かめた食い違い**: 記事は rules を「起動時に自動読み込み」として扱っているが、現在の公式資料では、対象を絞る指定を付けたルールは一致するファイルを扱ったときだけ読み込まれる（`REF-017`）。層の設計はもう一段細かくできる。
- **採用・実験の裏付け**: [foundation/README.md](../foundation/README.md) の適用の原則、[foundation/claude-code/README.md](../foundation/claude-code/README.md) の置き場所の判断表。

### ART-004 Agent SOP を整備させる

- **URL**: <https://zenn.dev/ryu1maniwa25/articles/fable5-agent-sop-setup>
- **記事種別**: 技術記事（導入記録）
- **現在の扱い**: `adopted`（2026-10-06 に再読して内容を具体化）
- **何が書かれているか**: 既存の OSS「Agent SOP」（`REF-021`）を手元のプロジェクトへ導入した記録。形式そのものは著者の考案ではなく、`.sop.md` に Overview・Parameters・Steps を必須で書き、制約は要求水準を表す標準の語（`REF-022`）で段階を付け、禁止には理由を添える。skill 形式への変換もできる。**記事の中心は導入手順ではなく、手順の出どころ**で、過去の作業記録をすべて読ませ、複数回繰り返された作業と今後も確実に再実施される手順を抽出させている。100本超の記録から40件の候補を出し、再利用の頻度で絞って13本にした。**記録に残った失敗が、禁止事項の「理由」としてそのまま埋め込まれた**点を成果として挙げ、生成物が組み込みの skill と名前で衝突することに自分で気づいて直した例も報告している。強いモデルが使えるうちに、という時限の動機で書かれているが、著者自身が「この頼み方自体はモデルを選びません」と断っている。
- **得られる示唆**: 要点は2つ。第一に、**手順を頭から考えずに記録から掘り出す**。そうすると、起きていない問題のための手順を書かずに済み、制約の理由まで実例から供給される。この向きは、評価を先に作れという公式の指針（`REF-014`）とも一致する。ただし掘り出しをモデルに任せても、採用の判断は人が行う（`REF-016`）。第二に、禁止事項に「なぜ禁止か」を併記する形は、禁止を判断材料へ戻す仕掛けとして読める。想定外の場面で読む人と agent の両方が判断できる。
- **再読で確かめた時限の前提**: 記事が前提にしていた利用枠の期限（2026年7月上旬まで、週間上限の一部）は既に過ぎている。方法そのものは残るが、「今やらないと使えなくなる」という動機づけの部分は現在は当てはまらない。ツールの採用可否は別問題で、公開元と形式は確認したが保守の現況は確かめていないため、導入を勧める判断はしていない。

### ART-006 Claude Code と Codex の設定同期

- **URL**: <https://zenn.dev/explaza/articles/20f7f41cff8428>
- **記事種別**: 技術記事（自作ツールの紹介）
- **現在の扱い**: `adopted`（2026-10-06 に再読し、扱う範囲の記述を修正）
- **何が書かれているか**: 同じプロジェクトで複数のコーディングエージェントを使うと、設定の変更が片方にしか反映されない問題への対処。対象は指示ファイルだけでなく、skills、hooks、MCP の設定、対象を絞るルールまで含む。**共有の軸に共通形式の指示ファイルを据えており**、Claude 側の入口ファイルからそれを取り込み、skill の置き場は共通の場所への symlink にする。形式が違う項目（JSON と TOML など）は中立な表現へ変換して突き合わせ、無関係な設定やコメントを保ったまま書き戻す。どちらが新しいかは更新時刻ではなく前回同期時の指紋で判定し、両側が変わっていれば利用者に選ばせる。同期する項目は対話的に選ぶ設計で、提供元ごとにプロンプトの推奨が違うため一律の同期は逆効果だとする。対象を絞るルールは相手側に対応する概念が無いため本体を同期せず、どのファイルをいつ読むかだけを正本へ書き出す。MIT ライセンス。
- **得られる示唆**: 共有できる事実は一つの正本へ寄せ、ツール固有の実行手順は各ツール側に残す、という切り分けが取れる。この記事が選んだ2つの判断は、後から各製品の公式仕様に追認された。指示ファイルを共通形式に寄せる点は公式の読み込み経路になり（`REF-001`）、skill の置き場を共通の場所にして symlink で参照する点は、Codex が共通の場所を探して symlink を辿ること（`REF-010`）と、Claude Code が skill 名の項目を symlink にできること（`REF-002`）で裏付けられる。一方で、記事の中核だった「差分を変換して双方向に同期する」部分は、指示ファイルに関しては公式対応により必要性が下がった。全項目を無理に同期しないという判断は変わらず有効。
- **採用・実験の裏付け**: [foundation/README.md](../foundation/README.md) の適用の原則、[foundation/agents-md/README.md](../foundation/agents-md/README.md) の「指示ファイル以外」と「無理に同期しない」、[skills/knowledge-curator/SKILL.md](../skills/knowledge-curator/SKILL.md)。

### ART-012 メモリを棚卸しする

- **URL**: <https://zenn.dev/cureapp/articles/c1e963064d05fd>
- **記事種別**: 技術記事（運用手順と自作 skill の紹介）
- **現在の扱い**: `adopted`（2026-10-06 に再読して内容を具体化）
- **何が書かれているか**: エージェントが自分で書いた記憶を定期的に棚卸しする方法。毎セッション読み込まれるのは索引ファイルの先頭一定量だけで、話題別ファイルは索引経由で必要時に読まれる、という前提を確認している（公式仕様と一致、`REF-001`）。核心の主張は**「古い記憶は、無いより悪い」**。空なら調べ直すが、古い記述が残っていると、それを前提に自信を持って動くからである。手順は6段階で、退避、計測（索引の行数とバイト数、件数、1件あたりの長さ、種類の分布、更新日の無いもの）、**外の事実との突き合わせ**（参照している課題や変更要求の状態を実際に引く、参照先ファイルの実在確認）、分類、**小分けでの承認**、反映と報告。判断基準も表になっており、済んだ作業・条件が満たされた注意書き・重複・リンク切れは保管へ、版管理やコードや課題管理から引き直せる情報は維持費の方が高い、**引き直せない知識（好み・判断の理由・落とし穴の場所）は残す**、全員に効く規則は個人の記憶ではなく共有の規則の層へ、索引の1行が長いものは話題別ファイルへ畳む。**製品に組み込まれた整理機能では見つからない**とも明記しており、理由は課題や変更要求の状態まで見ないからである。頻度は月1回程度が目安で、上げすぎると圧縮のたびに詳細が落ちる。やってはいけないこととして、承認なしに消すこと、未確認の推測を確定事項として出すこと、索引を短くするために詳細を捨てること、まとめて承認を求めることを挙げる。最後に、管理が重いなら記憶の仕組みを切る選択もある、と触れている。
- **得られる示唆**: 追加する仕組みとは別に、鮮度を点検する仕組みが要る。要点は、点検が**外の世界を見に行く**ことである。内部の重複や長さは機械的に直せるが、「外が変わったこと」は外を引かないと分からない。残す基準が「引き直せるかどうか」なのも効いていて、調べ直せる事実を抱えるほど維持費だけが増える。頻度そのものが設計対象で、上げすぎは詳細の喪失を招く。なお、この手順が必要な理由は独立した実測でも裏付けられる（`REF-019`）。作業の最中にエージェント自身が古さに気づくことは期待できないため、棚卸しを別の活動として明示的に行う形が妥当である。一方で記事に無い観点として、1件直したときにそれに依存する記述も見る必要がある。
- **採用・実験の裏付け**: [foundation/README.md](../foundation/README.md)、[foundation/memory-upkeep/README.md](../foundation/memory-upkeep/README.md)（自動の記憶の棚卸し手順）。

### ART-015 肥大化し続ける CLAUDE.md

- **URL**: <https://zenn.dev/tokium_dev/articles/claude-md-keeps-growing>
- **記事種別**: 技術記事（観察と対処の記録）
- **現在の扱い**: `adopted`（2026-10-06 に再読して内容を具体化）
- **何が書かれているか**: 一度整理した指示ファイルが数週間で2.8倍に膨らんだという観察と、その予防策。**原因を判断の質ではなく「合計が見えないこと」に置く**のが要点で、一つ一つの追記はどれも正しく見えるのに合計だけが増え続ける、意識して見に行かない限り合計は目に入らない、と述べる。対処は、書き込み後に走る hook から35行の小さなスクリプトを呼び、本体のバイト数が上限（12,288バイト）を超えたら**削除ではなく移動**を促す文面を返す形。移動先の規則も決めてあり、一度きりの手順は別の文書へ（本体には開く場面を示す1行だけ残す）、対象が限られる規則は条件付き読み込みの層へ（`paths:` を付ける前提）、失効した規則は保管用の場所へ（消さない）。導入前の7日で170→378行・13,512→38,071バイト（+181.8%）、導入後の7日で130→131行・10,979→11,114バイト（+1.2%）という前後の値を載せている。
- **得られる示唆**: 肥大化は一度の整理では解決せず、継続的な予防のほうが効く。移す先を先に決めておけば、追記そのものを断らずに本体を短く保てる。上限の監視を人の記憶ではなく仕組み側に置く点が要点で、**同じ対象を同じ単位で前と後に測っている**ので数字の作り方も妥当（ただし1人の環境の記録で、本人が意識し始めた効果と分けられてはいない）。
- **再読で確かめた食い違いと不足**: 止める力について、この hook はツールの実行**後**に走るイベントを使っているため、書き込みそのものは止まらない。異常を返しても内容がモデルに渡るだけで、実際に止めるなら実行前のイベントで拒否する必要がある（`REF-020`）。また、監視しているのは本体1ファイルのバイト数だが、常時読み込まれるのはそれだけではない（条件なしのルール、skill の名前と説明、まとめ配布の中身、自動の記憶の索引も毎回載る。`REF-017`、`REF-002`、`REF-011`）。1ファイルだけを見張ると、条件を付けずに別ファイルへ移した操作を改善と読み違える（`ART-003`）。記事自身の診断（合計が見えない）を活かすなら、測る範囲を層の合計へ広げる。
- **採用・実験の裏付け**: [foundation/README.md](../foundation/README.md)、[foundation/claude-code/README.md](../foundation/claude-code/README.md)（本体を短く保ち、詳細は skill または参照文書へ移す方針）、[foundation/instruction-upkeep/README.md](../foundation/instruction-upkeep/README.md)（合計を仕組みで見えるようにする節）。

### ART-017 AIコードレビューの判断配置

- **何が書かれているか**: コードレビューの判断を、機械的に証明できる検査、明示ルールで候補を絞る検出、複数の成果物の意味を読むAIレビュー、責任を伴う人間の最終判断の4層に分ける設計を説明している。同じ指摘を繰り返す場合は条件をルールやテストへ移す一方、意味・例外・責任の判断まで無理に機械化しない。決定論的なcommandでも、レビュー対象側が実行許可を変更できないtrust boundaryが必要だとする。

### REF-054 停止条件を書かないと実際に止まらない

- **URL**: <https://arxiv.org/abs/2607.01641>
- **記事種別**: 査読前論文（静的解析ツールの提案と、その著者らによる評価）
- **現在の扱い**: `reference`
- **何が書かれているか**: エージェントが反復の途中で終了できず、モデル呼び出しや道具の実行を繰り返し続ける現象を扱う。費用の増加とサービス停止につながるとする。6,549 のエージェント実装を静的解析し、47 プロジェクトで 68 件を手で確認した（報告された精度 91.9%）。
- **得られる示唆**: 停止条件の欠落は理屈上の心配ではなく、**公開されている実装に実際に残っている**。回す前に、反復回数または時間の上限と、同じ失敗が続いたときに降りる条件を書く理由がここにある。査読前で評価も著者ら自身によるため、**採るのは向きだけで、件数や精度は移さない**。
- **採用・実験の裏付け**: 該当なし（`reference` のため）。反映先は [../foundation/autonomous-loop-delegation/README.md](../foundation/autonomous-loop-delegation/README.md)（未検証）。
